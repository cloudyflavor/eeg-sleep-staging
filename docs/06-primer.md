## 1. 2단계 분리 — npz 와 parquet

- **npz** = numpy 배열 여러 개를 한 파일에 담는 포맷. 녹음당 하나씩 "신호 + 라벨 + 부가정보"
- **parquet** = 표(행×열) 전용 파일 포맷. 학습에 넣을 숫자 표

전처리를 한 번에 하지 않고 두 단계로 쪼갰다.

```
[1단계]  EDF ──→ 에포크 npz      정보를 잃지 않는 처리만 (읽기·30초 자르기·라벨)
[2단계]  npz ──→ 특징 parquet    비교하고 싶은 처리 전부 (필터·정규화·특징)
```

요리에 비유하면:

```
1단계 = 장보고 재료 손질해서 냉장고에 넣기   (오래 걸림, 한 번만)
2단계 = 꺼내서 조리법 바꿔가며 요리          (빠름, 여러 번)
```

우리 실험은 "필터를 걸까 말까, 정규화를 어떻게 할까" 를 **비교하는 것**이고,
그 비교 대상이 전부 2단계에 있다.

**안 나눴다면** — 필터를 바꿔볼 때마다 EDF 153개(40 GB)를 처음부터 다시 읽어야 한다
(1회 24분). 나눴기 때문에 9가지 조합을 npz 는 그대로 두고 설정만 바꿔 만들었다.

기준은 **되돌릴 수 있는가** 다. 필터 건 신호에서 원본은 복원할 수 없다.
그래서 되돌릴 수 없는 처리는 1단계 산출물에 굽지 않았다.

## 2. 중앙값 Welch — 잡음을 지우는 대신 잡음에 안 흔들리는 통계

### 용어

뇌파는 여러 속도의 파동이 **겹쳐진** 신호다.

- **주파수 분해** = 겹친 걸 분리해 "느린 성분이 얼마, 빠른 성분이 얼마" 를 세는 것
- **스펙트럼 / PSD** = 주파수별로 힘이 얼마나 실렸는지의 그래프.
  "델타(1–4 Hz)에 52 %, 방추(12–16 Hz)에 6 %" 가 여기서 나온다
- **Welch** = 이걸 계산하는 방법 이름 (1967년 Peter Welch)

### Welch 가 하는 일

30초를 통째로 분해하면 잡음에 취약하다. Welch 는 겹치는 5초 조각 ~11개로 나눠
각각 분해한 뒤 **하나로 합친다.**

### 합칠 때 평균 대신 중앙값

```
11조각의 델타파워:  10, 11, 10, 12, 11, 10, 11, 10, 12, 11, 380
                                                        ↑ 1초 몸 뒤척임

평균   = 44.4   ← 잡음 하나가 4배로 끌어올림
중앙값 = 11     ← 거의 안 움직임
```

**이 선택 덕분에 아티팩트 제거 단계가 아예 없다.** 잡음 에포크를 골라 버리는 방식은
실험 설정마다 버려지는 에포크가 달라져 **평가 대상 자체가 달라지고** 비교가 무너진다.
실제로 구 파이프라인의 "500 µV 초과 제거" 규칙은 EDFX 에서 검출률 0 % 였다.

**대가**: 중앙값은 평균보다 통계 효율이 약간 낮다. 잡음 없는 구간에선 평균이 미세하게
정확하다. 그 손해로 견고함을 샀다.

## 3. 누적(expanding) 정규화 — "이 사람 기준" 을 미래 없이

### 왜 정규화하나

사람마다 뇌파 진폭이 다르다 (두개골 두께, 전극 접촉, 나이).

```
A씨:  델타파워  얕은 잠 10, 깊은 잠 40
B씨:  델타파워  얕은 잠 30, 깊은 잠 120    ← 원래 3배 큰 사람
```

절대값 40 은 A씨에겐 깊은 잠, B씨에겐 얕은 잠이다. **정규화 = "이 사람 기준으로
높은가" 로 바꾸는 것.**

### robust 와 분위수

```
정규화값 = (지금 값 − 중앙값) ÷ (95분위 − 5분위)
```

- **분위수** = 줄 세웠을 때의 위치. 95분위 = 상위 5 % 지점
- **robust** = 평균·표준편차 대신 중앙값·분위수. 극단값에 안 흔들린다

### 문제와 선택

중앙값·분위수는 **전체를 줄 세워야** 나온다. 밤이 끝나야 그 밤의 중앙값을 안다.
웨어러블은 자는 도중 판정해야 하므로 미래가 없다.

```
사후     밤 전체로 통계          ← YASA. 아침에만 가능
누적     1번부터 지금까지        ← 우리 선택. 밤이 깊어질수록 사후에 수렴
이동창   최근 60분만             ← 사후에 영영 수렴 안 함
```

이동창은 실시간의 손해가 밤새 계속되고, 누적이면 **밤 초반에만** 몰린다.

### 지연 예산을 정규화에도 쓸 수 있다 (2026-08-26 추가)

10분 지연을 허용하면 에포크 t 의 판정을 t+20 시점에 내보내므로, 통계도
[0 ~ t+20] 으로 계산할 수 있다. **효과가 가장 큰 곳이 밤 초반이다** — warmup 직후
표본 20개에 미래 20개를 더하면 표본이 두 배가 된다.

특징 쪽은 이미 이 원리를 쓴다 (중심 평활 = 미래 3.5분, 시프트 `_ep+1` = 미래 30초).
정규화만 lookahead 0 을 강제한 것이 일관성이 없었다. 구현은 누적 통계를 `shift(-D)`
하는 한 줄이므로, **지연 예산 실험의 축으로 미뤘다** (지금 넣으면 조합 9 → 27).

## 4. warmup 20 + 절단 구간만 계산 — 실제 기기의 하룻밤을 흉내

### 절단(crop)

이 데이터는 1990년경 **집에서 24시간 연속 녹음**한 것이다. 절반 이상이 낮에 깨어 있는
구간이다. 실제 기기는 자기 전에 쓰고 아침에 벗는다. 그래서 잠든 구간 앞뒤 30분만
남긴다 — 데이터 손질이 아니라 **배포 조건을 흉내 내는 것.**

### warmup

누적 정규화는 표본 20개(10분)가 쌓이기 전엔 값을 내지 않는다
(표본 3개로 낸 분위수는 통계가 아니라 잡음이다). 이 처음 10분이 warmup 이다.

### 순서 시행착오 — 두 번 고쳤다

| 설계 | 문제 |
|---|---|
| 절단 후 정규화 | 잠든 구간 첫 10분이 결측. 실제 기기는 착용 후 계속 쌓고 있었으므로 **가짜 핸디캡** |
| 녹음 전체로 정규화 후 절단 | "잠들기 8시간 전부터 켜 놓았다" 가 된다. 그런 사용자는 없다. 계산도 3배 낭비 |
| **crop_lo − 20 부터 계산** | **"잠들기 40분 전 착용"** = 실제 시나리오. 계산 3배 절감 |

warmup 구간은 통계를 세우는 데만 쓰고 학습에는 넣지 않는다. 인과 필터의 초기
과도응답(시작 직후 몇 초의 불안정)도 10분이면 함께 해소된다.

**대가**: 정규화가 표본 20개로 시작해 밤 초반 값이 튄다. 실제 기기도 정확히 그
조건이다 — 안정성이 아니라 **배포 조건과의 일치**가 목표다.

## 5. 직접 구현 + 벡터화 — 루프를 피하고 계산을 투명하게

### 벡터화

numpy 는 배열 전체를 한 번에 계산할 때 빠르다 (내부가 C). 파이썬 반복문으로 하나씩
돌면 수십 배 느리다.

```python
for i in range(841):  # 루프 — 매번 파이썬 오버헤드
    out[i] = std(epochs[i])

out = epochs.std(axis=-1)  # 벡터화 — 한 번에 841개
```

### 왜 antropy 를 안 썼나

엔트로피·Hjorth 를 계산해 주는 `antropy` 가 있고 YASA 도 쓴다. 그런데 일부 함수가
**1차원 배열만 받아** 에포크 수만큼 루프를 강제한다. 우리 특징은 정의가 짧아
(Hjorth = 분산 몇 번, MMD = 최대·최소 찾기) 직접 벡터화가 가능했다.
부수 효과로 "이 숫자가 뭔지" 를 코드가 그대로 보여준다.

**대가**: 직접 짜면 내가 틀릴 수 있다. → 실제 데이터로 값 범위를 대조했고
(진폭 중앙값이 이전 실측과 일치), 단위 테스트를 붙였다.
