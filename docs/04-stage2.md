# 2단계 전처리 — 결정과 근거

에포크 npz 를 특징 parquet 으로 바꾸는 단계. **비교 실험의 축이 전부 여기 있다.**

1단계 결정은 [`06-preprocessing-stage1.md`](06-preprocessing-stage1.md).
1단계가 "정보를 잃지 않는 처리만" 했기 때문에, 여기서는 npz 를 다시 만들지 않고
설정만 바꿔 몇 번이고 다시 돌릴 수 있다.

## 0. 북극성 — 웨어러블에서 돌아갈 수준

2026-08-26 확정. 이게 나머지 선택의 기준이 된다.

병원 PSG 는 전극이 20개 넘고, 비싸고, 하룻밤밖에 못 잰다.
**EEG 1~2채널이면 헤드밴드로 잴 수 있고, 집에서 여러 밤 잴 수 있다.**
"집에서 여러 밤 재서 수면 구조의 추이를 본다" 는 건 PSG 가 구조적으로 못 하는 일이다.

이 목표가 만드는 제약이 하나 있다 — **미래를 얼마나 볼 수 있는가.**

### 지연 예산 (delay budget)

특징마다 **필요한 미래 시간**이 다르다. 이걸 명시적 설계 변수로 다룬다.

| 특징 | 필요한 미래 | 예산 10분에서 |
|---|---|---|
| 대역파워 · Hjorth · 엔트로피 (에포크 하나) | 0초 | ✅ |
| MMD · Esis | 0초 | ✅ |
| 인과 필터 (`lfilter`) | 0초 | ✅ |
| 영위상 필터 (블록 단위) | 수 초 | ✅ |
| 과거 평활 2분 (`rollp`) | 0초 | ✅ |
| 시프트 +1, +2 에포크 | 1분 | ✅ |
| **중심 평활 7.5분 (`rollc`)** | **3.5분** | ✅ |
| 다중 윈도 90초 | 30초 | ✅ |
| 밤 전체 정규화 | 밤이 끝날 때까지 | ❌ |
| YASA `time_norm` (경과 비율) | 밤이 끝날 때까지 | ❌ |

> **YASA 는 이미 실시간이 아니다.** 중심 평활 7.5분이 미래 3.5분을 요구한다.
> 아무도 이걸 "지연 3.5분" 이라고 명시하지 않는데, 사후 분석 전제로 만들어졌기 때문이다.
> **10분 예산이면 YASA 방식이 그대로 들어온다.**

**최종 산출물로 노리는 것**

```
지연 예산    0분      2분      5분      10분     무제한(사후)
macro-F1     ?        ?        ?        ?        ?
```

"웨어러블에서 지연을 N분 허용하면 성능이 얼마나 회복되는가."
문헌은 대부분 사후 분석 아니면 완전 실시간 둘 중 하나만 다룬다.

### 스트리밍 구현은 미루고, 장부만 지금 적는다

**학습은 배치가 맞다.** 스트리밍으로 학습하는 방식은 없고, 실시간은 추론에만 해당한다.
게다가 실시간 데이터가 아직 없다.

미뤄도 되는 이유는 **다시 짤 일이 없기 때문**이다. 두 종류를 구분해야 한다.

| | 배치 vs 스트리밍 | 지금 결정해야 하나 |
|---|---|---|
| 중심 평활 · 시프트 · 영위상 필터 | **나오는 숫자가 같다.** 타이밍만 다르다 | ❌ 지연 버퍼만 얹으면 된다 |
| **밤 전체 정규화 vs 누적 정규화** | **나오는 숫자가 다르다** | ✅ 사후로 학습해 놓고 실시간에 누적을 넣으면 train/serve skew |

두 번째가 [D11](#d11-정규화--원본--누적expanding-robust) 이고, 거기서 누적으로 정했다.
**그래서 나머지는 미뤄도 안전하다.**

**다만 `lookahead_epochs` 장부는 지금부터 적는다.** 스트리밍을 만드는 게 아니라
컬럼마다 정수 하나를 붙이는 것이고, 나중에 예산을 넣으면 자동으로 걸러진다.
지금 안 적으면 나중에 특징 수십 개를 손으로 되짚어야 한다.

**지연 예산 실험 자체는 Phase 1 이 끝난 뒤로 미룬다** — 지금 넣으면 축이 하나 더 늘어 조합이 폭발한다.

## 절단은 비교하지 않는다

EDFX Sleep-Cassette 는 1987–1991년에 **집에서 24시간 연속 녹음**한 데이터다.
나이가 수면에 미치는 영향을 보려던 연구라 자는 시간만이 아니라 하루 전체를 쟀다.

```
SC400N1 의 하루 (2,650 에포크 = 22시간)
  0 ────────────── 961 ══════════ 1741 ─────────────── 2650
  └─ 낮에 깨어있음 ─┘  └─ 잠든 구간 ─┘  └─ 낮에 깨어있음 ─┘
      약 8시간            약 6.5시간          약 7.5시간
```

**실제 기기는 자기 전에 쓰고 아침에 벗는다.** 22시간짜리로 학습해 놓고 8시간짜리
기기에 넣으면 분포가 안 맞는다. 절단은 데이터를 손보는 게 아니라 **배포 조건을 흉내 내는 것**이다.

점수가 유리해지는 방향도 아니다 — 안 자르면 W 가 68.8 % 라 "전부 각성" 만 찍어도
정확도 68.8 % 가 나온다. 자르면 다수클래스 기준선이 46.4 % 로 내려간다.

> 남는 약점 하나: 자를 위치를 **정답 라벨을 보고** 정한다. 실제 기기는 언제 잠들었는지
> 미리 모른다. 앞뒤 30분을 남기는 건 "눕고 나서 잠들기까지, 깨고 나서 벗기까지" 를
> 대략 흉내 낸 것이다.

**그래서 설정 축에서 뺐다.** 1단계 npz 는 여전히 전체 신호를 갖고 있어 되돌릴 수는 있다.

## D10. 필터 — 셋 다 비교

밴드패스 0.4–30 Hz. 아래는 이 아래위를 깎는다.

| 주파수 | 정체 | |
|---|---|---|
| 0.1 Hz 이하 | 땀·호흡으로 전극이 흔들리며 생기는 느린 표류 | ❌ |
| 0.4–30 Hz | 델타·세타·알파·방추·베타 — 판정 근거 전부 | ✅ |
| 50/60 Hz | 전원 잡음 | ❌ |
| 70 Hz 이상 | 근육 떨림 | ❌ |

### 인과 vs 영위상

```
인과 (lfilter)        지금 값 = f(지금, 과거)         → 신호가 뒤로 밀린다 (위상 왜곡)
영위상 (sosfiltfilt)  앞→뒤 한 번, 뒤→앞 한 번        → 밀림이 상쇄된다. 미래가 필요
```

| | 지연 | 위상 | 레퍼런스 |
|---|---|---|---|
| **A. 없음** | 0초 | — | DeepSleepNet (원신호를 그대로 CNN 에) |
| **B. 인과** Butterworth 5차 | 0초 | 왜곡 | sleep-linear — **DeepSleepNet 을 이겼다** |
| **C. 영위상** FIR | 수 초 | 보존 | YASA |

**세 레포가 셋 다 다르다. 정답이 정해져 있지 않다는 뜻이므로 우리가 잰다.**

**A 를 빼면 안 되는 이유** — EDFX 는 하드웨어에서 이미 0.5–100 Hz 로 필터링됐고,
대역파워를 Welch PSD 로 내면 시간영역 밴드패스가 **원리적으로 불필요**하다.
"필터가 값어치가 없다" 는 결과가 나오면 웨어러블에서 연산을 통째로 뺄 수 있다.

**인과가 괜찮을 수 있는 이유** — 우리가 뽑는 건 30초 안의 통계량(분산, 대역파워)이고,
이건 파형이 조금 밀려도 값이 거의 안 변한다. **위상에 둔감한 특징**이다.
sleep-linear 이 인과 필터로 DeepSleepNet 을 이긴 게 그 방증이다.

## D11. 정규화 — 원본 + 누적(expanding) robust

### YASA 가 하는 것과, 왜 그대로 못 쓰는가

YASA 는 **원본은 그대로 두고 평활본 두 개만** 녹음 단위 robust z-score 한다.

```python
rollc[rollc.columns] = robust_scale(rollc, quantile_range=(5, 95))
# 원본 features 는 손대지 않는다
```

**논문에 근거가 있다** (Vallat & Walker 2021, eLife):

> 정규화하는 이유 — *"there is marked natural interindividual variability in EEG brainwaves,
> meaning that each individual has a unique EEG fingerprint"*
>
> 원본을 남기는 이유 — *"The raw features were included to **increase the temporal specificity**
> and keep **absolute values that can be compared across individuals**"*

| | 답하는 질문 | 잃는 것 |
|---|---|---|
| 원본 | "델타파워가 절대적으로 큰가?" | 사람·장비마다 진폭이 달라 흔들린다 |
| 정규화본 | "이 사람의 오늘 밤 기준으로 높은가?" | 절대 크기 |

**부수 효과**: 두 방식 모두 *녹음 안에서* 정규화한다. 학습셋 전체 통계로 스케일러를 fit 하는
방식이 아니므로 **train/test 스케일러 불일치가 구조적으로 불가능하다.**

**그런데 `robust_scale` 은 중앙값과 분위수를 쓴다.**

```
정규화값 = (x − 중앙값) / (95분위 − 5분위)
```

중앙값·분위수는 "전체를 줄 세워 가운데를 찾는" 계산이라 **그 밤의 모든 에포크를 알아야 한다.**
에포크 500번을 계산하려면 501~1000번이 필요하다. **실시간에는 존재하지 않는 값이다.**

### 결정 — 누적(expanding) 통계

```python
med = feat.expanding(min_periods=20).median()
lo  = feat.expanding(min_periods=20).quantile(0.05)
hi  = feat.expanding(min_periods=20).quantile(0.95)
normalized = (feat - med) / (hi - lo)      # lookahead = 0
```

| | 통계 범위 | lookahead | 문제 |
|---|---|---|---|
| 사후 (YASA) | 밤 전체 | **밤 끝까지** ❌ | 실시간 불가 |
| **누적** ← 채택 | 1 ~ 지금 | **0** ✅ | 밤 초반 불안정 |
| 이동창 60분 | 최근 120 에포크 | 0 ✅ | 밤이 깊어져도 사후에 수렴하지 않는다 |

**누적을 고른 이유**: 밤이 깊어질수록 **사후 값에 수렴한다.**
에포크 600 시점이면 표본 600개라 사후와 거의 같다.
이동창은 아무리 시간이 지나도 최근 60분만 본다 — "실시간의 대가" 가 밤 전체에 퍼진다.
누적이면 그 대가가 **밤 초반에만 집중**된다.

**밤 초반은 NaN 으로 둔다.** `min_periods=20` (10분) 미만이면 결측이다.
부스팅 트리는 결측을 네이티브로 처리한다 (HistGradientBoosting·XGBoost·LightGBM·CatBoost 전부).
**억지로 0을 채우는 거짓말을 하지 않아도 되고**, 모델은 "밤 초반이라 정규화 값이 없음" 을
하나의 상태로 배운다.

**사후 방식도 같이 잰다 — 상한선으로.** 코드는 같고 통계 범위만 다르므로 비용이 거의 0이다.

**지연 정규화 변형 (2026-08-26, 지연 예산 실험에서 다룬다).** 지연 D 를 허용하면
에포크 t 의 판정을 t+D 에 내보내므로 통계도 [0 ~ t+D] 로 계산할 수 있다
(누적 통계를 ``shift(-D)`` 하면 된다). 효과가 가장 큰 곳이 밤 초반이다 — warmup
직후 표본 20개에 미래 20개(10분)를 더하면 표본이 두 배가 된다. 특징 쪽(중심 평활,
시프트 ``_ep+1``)은 이미 이 원리를 쓰고 있으므로 정규화만 lookahead 0 을 강제할
이유가 없다. Phase 1 에 안 넣는 건 축이 하나 늘면 조합이 9 → 27 이 되기 때문이다.

```
사후 정규화  →  도달 가능한 상한선 (실시간 불가)
누적 정규화  →  실제로 배포 가능한 값
   차이     =  실시간의 대가
```

> 같은 이유로 YASA 의 `time_norm = times / times[-1]` 은 쓰지 않는다 (밤 길이를 알아야 한다).
> `time_hour`(단순 경과 시간)는 쓴다.

## D12. 시간 문맥 — 없음 / 평활 / 시프트

**수면 단계는 앞뒤 맥락 없이 못 정한다.** 깊은 수면 직후의 얕은 수면과 REM 직전의 얕은 수면은
파형이 비슷하지만 **어디에서 왔는지**가 다르다.

### A. 평활 (YASA)

이웃 에포크 특징의 이동평균을 열로 추가한다. 중심 7.5분(미래 3.5분) + 과거 2분(미래 0).

- ✅ 열이 특징 수 × 2 로 끝난다. 잡음이 눌린다
- ❌ **평균이라 순서가 사라진다.** "올라가는 중" 과 "내려가는 중" 을 구분 못 한다

### B. 시프트 (sleep-linear)

특징 열을 시간축으로 밀어서 붙인다.

```
에포크 102 행:
  delta_now  delta_m60  delta_m30  delta_p30
    18.2       12.3       15.7       11.4
              1분 전     30초 전    30초 후
```

```python
for lag in [-2, -1, 1, 2]:
    shifted = df.groupby("recording")[cols].shift(lag)
    #          └─ 없으면 A 라는 사람의 마지막 에포크가 B 의 첫 에포크를 참조한다
    df = df.join(shifted.add_suffix(f"_lag{lag}"))
```

- ✅ **순서·방향이 보존된다.** "직전보다 델타가 올랐다" 를 트리가 직접 배운다
- ❌ 열 폭증. 특징 60개 × 시프트 4개 = 240열. 유효 표본이 78명인데 위험하다

> **⚠️ 우리 데이터의 함정.** 판독불가 제거로 시간축 구멍이 **1,104개** 있다.
> `shift(1)` 이 "30초 전" 이 아니라 "3분 전" 일 수 있다.
> → `epoch_idx` 로 실제 간격을 확인해 간격이 1이 아니면 NaN 을 넣는다.
> 1단계에서 `epoch_idx` 를 저장해둔 게 여기서 값을 한다.

### C. 다중 윈도 — 나중으로 미룬다

같은 특징을 30 / 60 / 90초 창에서 세 번 뽑는다. 시간·주파수 해상도 상충을 완화한다.

미루는 이유: 1단계 npz 가 이미 30초로 잘려 있어 90초 창을 만들려면 에포크를 이어붙여야 하고,
구멍·경계 처리가 얹힌다. 계산도 3배다. **시프트와 정보가 상당히 겹칠 가능성도 있다.**

### D. 없음 — 기준선

**반드시 필요하다.** 시간 문맥이 얼마나 벌어주는지 재려면 기준선이 있어야 한다.

### 왜 A 와 B 를 비교하는가

**YASA 와 sleep-linear 이 여기서 갈렸다.** 하나는 평활, 하나는 시프트.
둘 다 논문으로 나왔고 **아무도 직접 비교하지 않았다.**

| | 필요한 미래 | 추가 열 |
|---|---|---|
| D. 없음 | 0 | 0 |
| A. 평활 | 3.5분 | ×2 |
| B. 시프트 | 1분 | ×4 |

셋 다 10분 예산 안이다.

### YASA 가 실제로 쓰는 것 (소스에서 확인)


| 대역 | 범위 | 무엇을 잡나 |
|---|---|---|

### 채널 간 특징 — 우리만 할 수 있는 것

우리는 2채널(Fpz-Cz, Pz-Oz)이다. **두 채널의 비율·차이**를 넣을 수 있다.
알파파는 뒤통수(Pz-Oz)에서 강하고 델타파는 이마(Fpz-Cz)에서 강하므로 **비율이 위치 정보를 담는다.**

> YASA 도 sleep-linear 도 단일 채널 기준이라 레퍼런스가 없다. 시도해볼 지점이고,
> 안 되면 안 된다는 것도 결과다.

### MMD · Esis — 기여도를 측정한다

출처: [Aboalayon et al., *Entropy* 18(9):272, 2016](https://www.mdpi.com/1099-4300/18/9/272).
Decision Tree 로 정확도 93.13% 보고.

| | 정의 |
|---|---|
| **MMD** (Maximum-Minimum Distance) | 30초를 작은 창으로 쪼개고, 각 창의 최댓값 지점과 최솟값 지점 사이의 **피타고라스 거리** √(Δ진폭² + Δ시간²) |
| **Esis** (EnergySis) | 진폭² 합 × 속도² 합 |

**보고된 93.13% 를 우리 숫자와 나란히 놓을 수 없다.** 이 계열 논문 대부분이 에포크 단위
무작위 분할로 평가한다. 우리 [`02-prior-art.md`](02-prior-art.md) 에 기록된 Memar & Faradji 2018
실측이 그 차이를 보여준다 — 에포크 단위 95.31% vs **피험자 단위 86.64%**, 8.7 %p.

**기존 특징과 겹칠 가능성이 크다.**

```
MMD  ≈ 진폭 범위 + 그 사이의 시간 간격
       └ 진폭 범위는 std·iqr 이 이미 담고 있다. 새로운 건 "시간 간격" 부분 (nzc 와 비슷한 축)
Esis ≈ 진폭² 합 × 속도² 합
       └ 진폭² 합 = Hjorth Activity, 속도² 합 = Hjorth Mobility 의 분자
       └ 사실상 Hjorth 두 개를 곱한 형태
```

**그래서 이렇게 다룬다.**

```
YASA 세트           → macro-F1  A
YASA 세트 + MMD·Esis → macro-F1  B
B − A 가 값어치
```

올라가면 개선이고, 안 올라가면 **"검증된 세트와 중복임을 실증"** 이다 — 둘 다 결과다.
비용은 거의 0 이다. **FFT 가 필요 없는 O(n) 시간영역 계산이고 미래를 안 본다(지연 0).**
웨어러블 관점에서 가장 싼 부류다.

## D15. 채널 축 — 1채널 vs 2채널

**Sleep-EDF 에서 단일 채널 Fpz-Cz 가 사실상 표준이다.**

| 모델 | 채널 |
|---|---|
| DeepSleepNet · TinySleepNet · SleepTransformer | Fpz-Cz **1채널** |
| YASA | EEG **1채널** (EOG/EMG 는 선택) |
| Van der Donckt 2023 | EEG 2채널 + EOG + EMG |

앞의 넷이 단일 채널로 MF1 0.77~0.81 을 낸다. **우리 2채널은 표준보다 많은 구성이다.**

**웨어러블 관점에서 이게 곧 실험이다.**

```
Fpz-Cz 1채널  →  헤드밴드 = 이마. 실제로 만들 수 있는 형태
Pz-Oz  1채널  →  뒤통수. 헤드밴드로는 어렵다
2채널          →  전극이 둘. 착용성이 떨어진다
```

**"두 번째 채널이 얼마를 벌어주나" 가 곧 "헤드밴드 하나로 충분한가" 다.**
비용은 거의 0 이다 — 특징 parquet 에서 열만 골라내면 된다.

## 문헌으로 확인된 것 (배경)

### Wake 절단 — 세 논문에서 독립 확인

- Van der Donckt et al. 2023: *"wake periods were trimmed to 30 minutes before and after the sleep period"*
- SleepTransformer (Phan 2022): *"recordings trimmed to ±30 min around the in-bed period"*

절단 후 W 비율 SC-78 **33.6%** — 우리 실측 33.74% 와 일치한다. **우리 계산이 표준과 맞다.**

### 라벨 처리

- R&K S3 + S4 → N3 병합 (우리는 DS)
- MOVEMENT / "Sleep stage ?" 는 버린다 (별도 클래스로 두지 않음)
- SleepTransformer 는 추가로 *"5개 단계가 모두 나타나지 않는 녹음은 제외"* 했다 — 우리도 적용할지 미정

### 데이터 증강 — 문헌 근거가 약하다

특징 기반 접근에서 증강 사례를 찾지 못했다. 딥러닝 쪽에는 있지만(시간 이동, 신호 반전 등)
**우리 접근에서는 근거 없이 쓰지 않는다.** 클래스 불균형은 가중치로 다룬다.

### 웨이블릿을 안 쓰는 이유

YASA·sleep-linear·Van der Donckt 셋 다 **Welch PSD** 를 쓴다. 웨이블릿은 이 계열에서 표준이 아니다.
30초 에포크 안에서 시간 해상도가 필요한 작업(방추 검출)이 아니라 **에포크 단위 요약**이 목표라
Welch 로 충분하다. **미뤄둔 실험 후보로만 남긴다.**
