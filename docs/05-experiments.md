# 1부. 부스팅 모델별 특징

## 셋의 근본적 차이 — 트리를 키우는 방식

| | **XGBoost** (2014) | **LightGBM** (2017, MS) | **CatBoost** (2017, Yandex) |
|---|---|---|---|
| 트리 성장 | **레벨 단위** (level-wise) | **리프 단위** (leaf-wise) | **대칭** (oblivious) |
| 모양 | 좌우 균형 잡힌 트리 | 깊고 불균형한 트리 | 한 레벨의 모든 노드가 **같은 분기 조건** |
| 결과 | 안정적, 과적합 덜함 | **빠르고 조금 정확**, 작은 데이터에서 과적합 위험 | 예측이 매우 빠름, 과적합에 강함 |

**리프 단위가 뭐냐** — LightGBM은 "지금 가장 손실이 큰 리프"를 골라서 거기만 쪼갭니다. 그래서 트리가 한쪽으로 깊게 자랍니다. 효율적이지만 **데이터가 적으면 그 한쪽만 파고들어 과적합**합니다.

**대칭 트리가 뭐냐** — CatBoost는 한 깊이에서 **모든 노드가 같은 조건**을 씁니다. 표현력은 조금 떨어지지만 예측이 극도로 빠르고(조건 몇 개만 확인) 과적합에 강합니다.

## 각자의 특기

| | 특기 | 우리 데이터에서 |
|---|---|---|
| **XGBoost** | 목적함수에 **정규화 항이 명시적**(L1/L2). 가장 성숙, 문서 풍부 | 무난 |
| **LightGBM** | **속도**. 히스토그램 기반 + GOSS/EFB 최적화 | 유리 (19.5만 행) |
| **CatBoost** | **범주형 변수** 처리. 누수 없는 target encoding | **우리 특징은 전부 연속값 → 주특기가 안 살아남** |

> **중요**: 우리 특징에 범주형이 없어서 **CatBoost의 최대 장점이 발휘되지 않습니다.**
> 그럼에도 sleep-linear이 CatBoost로 좋은 결과를 냈으니 후보에는 둡니다.

## 설치·실행 제약

| | 추가 설치 | 맥 | 서버 |
|---|---|---|---|
| XGBoost | 필요 | **libomp 필요** | 미설치 |
| LightGBM | 필요 | **libomp 필요** | 미설치 |
| CatBoost | 필요 | 문제 없음 | 미설치 |
| **sklearn `HistGradientBoosting`** | **불필요** (sklearn 내장) | ✅ | 미설치 |

LightGBM 방식을 sklearn이 구현한 게 `HistGradientBoosting`입니다. 기능은 적지만 **의존성이 없습니다.**

## 조합(앙상블) 방법

| 방법 | 어떻게 | 특징 |
|---|---|---|
| **소프트 보팅** | 각 모델의 **확률을 평균** | 가장 단순. 보통 잘 됨 |
| 하드 보팅 | 예측 클래스 다수결 | 확률 정보를 버림 |
| 가중 평균 | 검증 성능에 비례한 가중치 | 가중치를 어디서 정할지 주의 |
| **스태킹** | 각 모델 출력을 입력으로 받는 **메타 모델** | 강력하지만 누수 위험 큼 |

**근거가 있는 데이터 포인트**: SLEEPYLAND(npj Digital Medicine 2026)의 **SOMNUS 앙상블이 소프트 보팅**이고, 개별 모델 대비 **94.9%의 경우에 우세**(그중 72.7%는 통계적으로 유의)했습니다.

> **스태킹 주의**: 메타 모델을 학습시킬 데이터가 필요한데, 이걸 잘못하면 누수입니다.
> 반드시 **out-of-fold 예측**으로 학습시켜야 합니다. 복잡도 대비 이득이 작으면 소프트 보팅으로 갑니다.

# 2부. 실험 설계

## 핵심 문제 — 순서의 함정

형님이 짚으신 지점입니다.

> 전처리를 모델 A로 최적화 → 나중에 모델 B로 바꿈
> → **A에만 좋았던 전처리를 고른 것일 수 있음**

이걸 **greedy optimization의 함정**이라고 합니다. 완전한 해법은 전부 조합해보는 것인데 (전처리 7 × 모델 5 = 35회) 비쌉니다.

### 채택하는 절충안

**전처리 실험을 모델 2개로 돌립니다.**

```
전처리 변형 7개  ×  { 선형 모델, 부스팅 1개 }  =  14회
```

- **두 모델에서 같은 방향이 나오면** → 모델에 안 휘둘리는 전처리 효과. 신뢰
- **엇갈리면** → 그 자체가 발견. "이 전처리는 선형에만 유리하다"

**왜 선형을 넣나** — 성격이 가장 다르기 때문입니다. 선형 모델은 정규화·스케일에 민감하고, 트리는 둔감합니다. 둘 다 좋아지는 전처리라면 진짜입니다.

## Phase 1 — 축 3: 전처리 (먼저 함)

| # | 바꾸는 것 | 기준 | 비교 대상 | 예상 효과 |
|---|---|---|---|---|
| P1 | **정규화** | 녹음 단위 robust | 전체 기준 / 정규화 없음 / **원본+정규화 둘 다** | **클 것** |
| P2 | **시간 문맥** | 이동평균 (7.5분+2분) | 시프트(±1,2 에포크) / 둘 다 / 없음 | **클 것** |
| P3 | 비싼 특징 | 전부 포함 | 순열엔트로피·프랙탈 제외 | 성능-비용 |
| P4 | 필터 | 영위상 0.4–30Hz | 없음 / 인과 | 작을 것 |
| P5 | Welch 집계 | 평균 | **중앙값** | 작을 것 |
| P6 | Wake 절단 | ±60 에포크 | 절단 없음 | 지표 해석이 바뀜 |
| P7 | 채널 | Fpz-Cz + Pz-Oz | Fpz-Cz만 / Pz-Oz만 | ? |

**실행 순서: P1 → P2 → P3 → (P1·P2가 미미하면 P4~P7 축소)**

앞의 둘에서 차이가 안 나오면 나머지도 안 날 가능성이 큽니다. 시간을 아낍니다.

**누적 방식**: 각 단계에서 이긴 설정을 다음 단계에 반영합니다(greedy). 다만 **P1과 P2는 상호작용이 있을 수 있어**(정규화 방식이 평활 효과에 영향), 이 둘만 **2×2로 교차 확인**합니다.

## Phase 2 — 축 2: 모델

Phase 1 에서 고른 전처리를 고정하고 모델만 바꾼다.

| 모델 | 역할 | 왜 넣나 |
|---|---|---|
| 다수클래스 | 절대 기준선 (46.4 %) | 이보다 못하면 아무 의미가 없다 |
| **로지스틱 회귀 (L2)** | 선형 기준선 | 부스팅이 얼마를 벌어주는지 재려면 필요하다. **다중공선성 대응** |
| **로지스틱 회귀 (L1)** | **특징 선택** | 97개 중 실제로 몇 개가 쓰이나 → 웨어러블 연산량과 직결 |
| HistGradientBoosting | Phase 1 에서 쓰던 것 | 빠르고 의존성이 없다 |
| XGBoost · LightGBM · CatBoost | 성장 방식이 다른 셋 | level-wise / leaf-wise / oblivious |
| 소프트 보팅 | 앙상블 | SLEEPYLAND 에서 94.9 % 의 경우 개별 모델을 이겼다 |

### 선형 모델을 넣는 이유

근거 논문이 바로 선형 모델이다. Van der Donckt 2023 의 제목이
*"Do not sleep on traditional machine learning"* 이고 레포 이름이 **sleep-linear** 다.
CatBoost 와 선형(SGD)을 나란히 쓴다. **우리가 선형을 빼면 그 논문과 직접 비교가 안 된다.**

L1 은 쓸모없는 특징의 계수를 정확히 0 으로 만든다. 우리 특징에는 실측된 중복이 있다
(`hmob` ↔ beta 상대파워 r = 0.84, `nzc` ↔ beta r = 0.86). **"97개 중 몇 개가 살아남나"**
에 답이 나오고, 그대로 웨어러블 연산량 절감으로 이어진다.

> 다만 상관이 높은 특징이 있으면 **L1 은 불안정하다** — 둘 중 하나를 임의로 고르는데
> fold 마다 다른 쪽을 고른다. 특징 선택이 목적이면 ElasticNet 이 더 안정적이다.

### 선형 모델에만 필요한 처리 — 비교가 오염되지 않게

부스팅에는 없는 제약이 셋 있다.

| | 부스팅 | 선형 |
|---|---|---|
| 결측 | 네이티브 처리 | **못 받는다** |
| 스케일 | 무관 (분할 기준만 찾는다) | **민감** (`abspow` 2847 vs `fdelta` 0.52) |
| 다중공선성 | 둘 중 하나를 쓰고 만다 | 계수가 폭주 → **L2 규제로 대응** |

**결측 처리를 모델마다 다르게 하면 "모델 차이" 인지 "결측 처리 차이" 인지 구분할 수 없다.**
→ 결측 38행(전체의 0.019 %)을 **양쪽 모두에서 제거**하고 같은 데이터로 비교한다.

**표준화는 선형 모델 파이프라인 안에 넣고 fold 별로 fit 한다.** 전체 데이터로 미리
스케일러를 맞추면 평가 fold 의 통계가 학습에 새어 들어간다.

## Phase 3 — 축 1: 하이퍼파라미터

**최고 모델 하나**에 대해서만 합니다.

### ⚠️ 여기가 가장 위험합니다

**하이퍼파라미터를 CV 성능 보고 고르면, 그 CV 성능이 낙관적으로 편향됩니다.** 테스트셋에 맞춰 튜닝한 셈이니까요.

**해결: 중첩 교차검증(nested CV) 또는 별도 튜닝 분할**

```
78명
 ├─ 튜닝용 피험자 20명  ← 여기서만 하이퍼파라미터 탐색
 └─ 평가용 피험자 58명  ← 최종 10-fold CV, 튜닝에 절대 안 씀
```

**간단한 쪽(별도 분할)을 권합니다.** 중첩 CV는 계산이 10배 늘어납니다.

> **정직하게**: 부스팅은 하이퍼파라미터에 관대해서 Phase 3의 이득이 작을 겁니다.
> Phase 1·2 결과를 보고 **생략해도 됩니다.**

| zerophase-smooth vs zerophase-none | +3.24%p | 10/10 | 0.002 | **문맥 효과 확실** |

| zerophase-smooth vs causal-smooth | +0.09%p | 5/10 | 0.846 | 구분 불가 |
| smooth vs shift (양쪽 필터) | +0.1~0.2%p | 7/10 | 0.16~0.56 | **통계적 무승부** |

## 읽기

- **시간 문맥이 지배적 요인** (+3.2%p, 10/10 fold). 수혜는 REM 이 최대
  (F1 0.686 → 0.770) — EEG 단독으로 애매한 LS↔R 을 이웃 맥락이 갈라준다.
  실측: 평활이 R 오탐(LS→R)을 13,192 → 7,259 개로 45% 줄였다.
- **필터는 작지만 진짜**: zerophase > none 이 문맥 없이도(9/10, p=0.027),
  평활 위에서도(8/10, p=0.020) 유지된다. zerophase ≈ causal 은 구분 불가.
- **평활 vs 시프트는 무승부.** 수치는 평활이 근소 우위지만 p>0.15.
  단 배포 특성이 다르다 — **lookahead 평활 3.5분 vs 시프트 1분**,
  열 수 289 vs 481. 지연 예산이 3.5분 미만인 시나리오에선 시프트가 대안.

  추론 비용 4배의 대가로 +0.16%p — 웨어러블 관점에선 단일 catboost 가 합리적,
  순위표용으로는 앙상블이 최고치.
- **lasso 의 특징 선택은 실패** — 기본 규제(C=1)가 17.6만 행 앞에서 너무 약해

# Phase 1.5 결과 — ablation (2026-08-27)

catboost / zerophase-smooth 고정. 전체(289열) 대비 각 구성을 뺀 효과.

| 구성 | 열 | macro-F1 | 차이 | 승 | p |
|---|---:|---:|---:|---:|---:|
| **전체 (기준)** | 289 | **0.8381** | — | — | — |
| MMD·Esis 제외 | 265 | 0.8356 | −0.27 %p | 1/10 | 0.006 |
| Fpz-Cz 만 | 139 | 0.8196 | −1.89 %p | 1/10 | 0.020 |
| Pz-Oz 만 | 139 | 0.7845 | −5.39 %p | 0/10 | 0.002 |
| 정규화 제외 | 145 | 0.8173 | −2.08 %p | 0/10 | 0.002 |

## 읽기

**채널** — 이마 단독(Fpz-Cz)이 0.820 으로 2채널 대비 1.9 %p 손실뿐이다.
헤드밴드로 만들 수 있는 게 이마 전극이므로 **"전극 하나로 거의 충분하다"** 는
실측 근거가 생겼다. 뒤통수 단독은 0.785 로 5.4 %p 손실 — 두 채널의 역할이
대칭이 아니며, Pz-Oz 는 이마가 못 보는 알파 계열 정보를 보태는 보조 역할이다
(Phase 2 중요도에서 `ratio__delta_front_back` 21위였던 것과 정합).

**정규화** — 빼면 2.08 %p 하락, 10/10 fold. **가장 큰 단일 기여**이며
채널 하나를 통째로 빼는 것보다 손해가 크다. 개인차 흡수가 실제로 일이 된다는
확증이고, 웨어러블에서 누적 분위수 계산을 생략하면 안 된다는 뜻이다.

**MMD·Esis** — 빼면 0.27 %p 하락. 크기는 작지만 10 fold 중 9개에서
전체가 이겼다 (p=0.006). **"기존 특징과 중복이라 값어치 없을 것" 이라던
사전 예측은 틀렸다** — 작지만 일관된 기여가 있다. Phase 2 중요도에서
Esis 평활본이 289개 중 19위였던 것과 방향이 같다. 비용이 O(n) 시간영역
계산에 lookahead 0 이라 유지한다.

## 결론

현재 구성(289열, 2채널, 정규화 포함, MMD·Esis 포함)이 최선이다.
**경량화가 필요하면 우선순위는 채널 → 거리특징 순**이고, 정규화는 마지막까지 남긴다.
