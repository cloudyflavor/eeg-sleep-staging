# 결정 기록

무엇을 정했고, 무엇과 비교했고, 실제로 얼마나 차이가 났는지를 남긴다.
실패한 것과 예상이 빗나간 것도 함께 적는다. 그것이 다음 판단의 근거가 된다.

`*` 표시된 수치는 밴드파워 적분을 고치기 전에 잰 것이다. 재실행이 끝나면 갱신한다.

---

## 1. 문제 정의

### 1.1 왜 4단계인가

**정한 것**: W / LS / DS / R 네 단계. N1 과 N2 를 LS 로 합쳤다.

**대안**: 5단계 W/N1/N2/N3/R.

**근거**: N1 은 전체의 소수이고 판독자끼리도 가장 많이 어긋나는 단계다. 웨어러블에서
얕은 잠을 N1 과 N2 로 나눠 알려줄 실익이 적다.

**대가**: **이 분야에서 가장 어려운 경계가 사라진다.** 5단계로 보고하는 문헌과 직접
비교할 수 없다. 문헌이 92% 를 보고해도 우리 수치와 나란히 놓을 수 없다.
이 점은 README 의 한계에 명시했다.

### 1.2 왜 EEG 두 채널만인가

**정한 것**: EEG Fpz-Cz, EEG Pz-Oz 두 개.

**대안**: EOG 와 EMG 를 더해 임상 표준에 맞추기.

**근거**: 이마에 붙이는 웨어러블은 안구운동과 턱 근전도를 얻기 어렵다.
그리고 EDFX 의 EMG 는 샘플링이 1Hz 라 사실상 쓸 수 없다.

**대가가 실제로 얼마인지 측정했다.** REM 은 원래 안구운동과 근전도를 함께 보고 판정한다.
그 두 채널이 없으니 REM 이 가장 약하다. R 의 F1 은 0.753 으로 네 단계 중 꼴찌이고,
REM 의 26.7% 가 얕은 잠으로 새어 나간다. **이것이 채널 선택의 값이다.**

### 1.3 두 채널을 함께 쓴 이유

**측정으로 정했다.** 채널을 하나씩 빼고 학습해 비교했다.

```
두 채널 전부        0.8381 *
이마만 남김        -1.84%p
뒤통수만 남김      -5.36%p
```

**이마가 뒤통수보다 세 배 중요하다.** 웨어러블을 이마에 붙이는 것이 자연스러운데
성능 면에서도 그쪽이 맞다는 근거가 된다.

다만 하나만 남기면 **채널 비교 특징이 통째로 사라진다.** 뒤통수 알파와 이마 알파의 비율,
이마 델타와 뒤통수 델타의 비율은 두 채널이 있어야 계산된다. 알파가 세다는 것만으로는
부족하고 **어디서** 센지를 알아야 각성과 얕은 잠이 갈린다.

## 2. 데이터 처리

### 2.1 중간 산출물에 무엇을 굽지 않았나

**정한 것**: EDF 를 30초 조각 npz 로만 바꾸고, 필터와 정규화는 굽지 않는다.

**대안**: 전처리를 다 적용한 최종 배열을 저장.

**근거**: 필터와 정규화는 비교 실험의 축이다. 구워버리면 조합을 바꿀 때마다
9.3GB 를 다시 만들어야 한다. **되돌릴 수 없는 처리는 뒤로 미룬다.**

**대가**: 특징 추출이 매번 필터부터 다시 한다. 조합 하나에 약 1분, 10종에 20분.
그 정도면 싸다.

### 2.2 아티팩트를 제거하지 않은 이유

**정한 것**: 제거하지 않고 지표만 저장한다. `ptp`, `std`, `flat_ratio`.

**대안**: 임계값을 넘는 조각을 버린다.

**근거는 측정이었다.** `ptp > 500µV` 기준으로 EDFX 전 파일을 훑었더니
**검출률이 평균 0.00%** 였다. EDFX 의 최대 ptp 가 약 353µV 라 절대 걸리지 않는다.
같은 기준을 HMC 에 대면 13.99% 가 걸리는데 대부분 ±800µV 하드 클리핑이다.

**임계값 하나로 두 데이터셋을 다룰 수 없다.** 그래서 제거 대신 지표를 남겨
나중에 "아티팩트가 많은 녹음이 성능이 나쁜가" 를 물을 수 있게 했다.

### 2.3 wake 절단

**정한 것**: 첫 비각성에서 60조각 앞, 마지막 비각성에서 60조각 뒤까지 남긴다.

**근거**: EDFX 카세트는 약 22시간을 녹음해서 절단 전에는 W 가 68.8% 다.
안 자르면 다 W 라고만 해도 정확도 68.8% 가 나온다.

**효과**: 41만 조각이 19만 5천으로 줄고, 클래스 분포가
W 33.7 / LS 46.4 / DS 6.7 / R 13.2 로 바뀐다.

**대가**: 절단 경계를 **정답 라벨로 정했다.** 실제 기기는 언제 착용했는지 모른다.
취침 시 착용을 전제한 것이고, 착용 시점을 모르는 상황에서는 다시 검토해야 한다.

## 3. 특징 설계

### 3.1 필터

```
없음        0.8267 *
과거만 봄   0.8316 *
앞뒤 봄     0.8347 *   ← 선택
```

**+0.8%p.** 하드웨어에서 이미 걸러져 나오므로 추가 필터가 필요한지 실험으로 확인했고,
작지만 있었다. 과거만 보는 필터와는 0.3%p 차이라, 실시간 제약이 강해지면
그쪽으로 바꿔도 손해가 적다.

### 3.2 시간 문맥

```
없음            0.7959 *
앞뒤 값 붙이기   0.8268 *   열 481개
앞뒤 평균       0.8267 *   열 289개   ← 선택
```

**+3.3%p 로 가장 큰 기여다.** 두 방식은 0.1%p 차이로 사실상 같은데
열 수가 481 대 289 다. **성능이 같으면 싼 쪽을 고른다.**

### 3.3 정규화

**정한 것**: 지나온 조각들로만 중앙값과 분포 폭을 잡는다.

**대안**: 밤 전체를 보고 잡는다. 아무것도 안 한다.

```
안 함          -2.07%p
과거만 봄       기준          ← 선택
밤 전체를 봄    쓸 수 없음
```

**밤 전체를 보는 방식은 성능과 무관하게 배제했다.** 아직 오지 않은 시간의 정보가
섞이고, 실제 기기에서는 계산할 수 없다.

미래를 안 본다는 것을 **동작으로 확인했다.** 80번 이후 값을 9999로 바꿔도
앞부분 결과가 변하지 않는 것을 검사로 고정했다.

### 3.4 거리 기반 특징

**빼봤더니 -0.25%p.** 거의 기여하지 않는다. 계산이 무겁지 않아 남겨뒀지만,
계산량을 줄여야 하면 가장 먼저 버릴 후보다.

### 3.5 특징 수

```
20개    0.802 *   -3.6%p
50개    0.830 *
100개   0.837 *   -0.3%p
289개   0.839 *
```

**100개면 충분하다.** 절반 이상은 없어도 된다. 20개까지 줄이면 무리다.

## 4. 분할과 평가

### 4.1 피험자 단위 분할

**정한 것**: 분할 키를 파일명이 아니라 피험자 번호로 잡고, 배정을 파일로 고정한다.

**근거**: EDFX 는 78명이 153녹음을 만든다. **75명이 2박씩 녹음했다.**
파일 단위로 나누면 같은 사람의 1일차가 학습에, 2일차가 평가에 들어간다.
같은 사람의 뇌파는 밤이 달라도 매우 비슷해서 성능이 부풀려진다.

**검사로 고정했다.** 같은 피험자가 학습과 평가에 동시에 없는지, 78명이 평가에
정확히 한 번씩 등장하는지, 예측 결과의 피험자가 그 묶음의 평가 대상과 맞는지를
전수로 확인한다.

### 4.2 왜 10묶음인가

**대안**: 5묶음.

**근거**: 78명을 10으로 나누면 평가 묶음마다 7~8명이다. 5로 나누면 15~16명이라
묶음별 성능의 흔들림은 줄지만 **학습에 쓰는 사람이 줄어든다.**
그리고 묶음이 많을수록 짝지어 비교할 표본이 늘어 통계 검정이 가능해진다.

### 4.3 지표

**macro-F1 을 주 지표로 쓴다.** 정확도는 다수 클래스에 끌려간다. 전부 LS 라고만
답해도 46% 가 나온다. macro-F1 은 네 단계를 똑같이 취급해서 DS 6.7% 를
못 맞히면 바로 떨어진다.

**기준선**: 한 클래스만 답하기. macro-F1 0.126, 정확도 0.337.
클래스 가중치를 같게 주면 W 를 답한다.

**비교 방법**: 같은 10묶음에서 폴드별 차이를 짝지어 Wilcoxon 검정한다.
평균만 비교하면 묶음 구성의 우연을 성능 차이로 착각한다.

## 5. 모델 선택

```
앙상블      0.840 *
catboost    0.839 *   ← 선택
xgboost     0.838 *
histgb      0.835 *
lightgbm    0.832 *
ridge       0.814 *
기준선      0.126 *
```

**선형에서 부스팅으로 +2.6%p.** 이 문제에 비선형이 필요하다.

선형 비교군으로 lasso 도 돌렸으나 **실험에서 뺐다.** 19만 행에서 좌표하강법이
2시간을 넘겼고, ridge 와 결론이 같아 얻는 것이 없었다. 선형 비교군은 하나면 충분하다.

**부스팅 네 종류는 0.5%p 안쪽이다.** 무엇을 골라도 큰 차이가 없다.
catboost 를 고른 이유는 성능이 가장 높았고 변수 중요도로 판단 근거를 캘 수 있어서다.

**앙상블은 0.2%p 더 높지만 쓰지 않았다.** 여러 모델의 확률 평균이라
왜 그렇게 판단했는지 캘 수단이 없다. 0.2%p 와 설명 가능성을 맞바꾼 것이다.

### 5.1 하이퍼파라미터

**무작위 탐색 8조합에서 0.5%p 미만.** 조정해서 얻는 것이 거의 없었다.
기본값을 쓴다.

### 5.2 클래스 가중치

**전체로는 동률이다.** 다만 `balanced` 는 DS +1.8%p, R −2.5%p 로 맞바꾼다.
어느 단계를 더 중요하게 볼지의 문제이지 성능 문제가 아니다.

## 6. 딥러닝 비교

### 6.1 왜 비교했나

손으로 설계한 특징과 신경망이 스스로 뽑은 특징 중 어느 쪽이 나은지 확인하기 위해서다.
**부스팅과 같은 분할, 같은 절단, 같은 지표를 쓰고 입력만 다르게 했다.**

### 6.2 조건을 맞추다가 발견한 것들

처음 비교는 조건이 다섯 군데 달랐다. 하나씩 맞추면서 문제를 찾았다.

**학습 회차를 평가 점수로 고르고 있었다.** 20회 돌린 뒤 평가 점수가 가장 좋은 회차를
채택했다. 부스팅에는 그런 절차가 없다. 부풀림을 측정하니 **CNN +1.61%p, LSTM +1.43%p**
였다. 학습용 피험자에서 검증용을 떼어내 거기서 회차를 고르도록 고쳤다.

**정규화 방식이 달랐다.** 신경망 쪽은 조각마다 그 조각의 통계로 맞추고 있었다.
미래를 보지는 않았지만 부스팅과 원리가 달랐고, 밤새 진폭이 어떻게 변하는지를 지웠다.
부스팅과 같은 방식으로 바꿨다.

**필터를 걸지 않고 있었다.** 부스팅에서 가장 좋았던 필터를 똑같이 걸도록 했다.

**채점 범위가 달랐다.** 묶음 가운데만 채점해서 각 녹음의 앞뒤 끝이 빠졌다.
양 끝 묶음이 그 자리까지 맡도록 고쳤고, 어긋나면 점수만 조용히 달라지므로
검사로 고정했다.

**맥락 창 크기가 달랐다.** 부스팅은 15조각인데 신경망은 20조각이었다.
제가 "비슷한 범위" 라고만 보고 맞추지 않은 것이다. 창 크기를 축으로 훑도록 바꿨다.

### 6.3 창 크기 실험

```
창    macro-F1   지연
 1     0.7907    0
 9     0.8258    2분     ← 최고
15     0.8189    3.5분
21     0.8199    5분
31     0.8121    7.5분
```

**맥락은 확실히 효과가 있다.** 창 1 대비 창 9 는 +3.51%p 이고 10묶음 전승, p=0.002.

**넓힐수록 좋아지지는 않는다. 창 9에서 정점이고 그 뒤로 내려간다.**
겹치지 않게 자르는 방식이라 창이 넓을수록 학습 표본이 줄어드는 것도 한몫한다.

**REM 이 가장 크게 올랐다.** 0.723 → 0.805 로 8.2%p. REM 은 길게 이어지는 상태라
조각 하나로는 얕은 잠과 구분이 안 된다. 반면 DS 는 0.706 → 0.720 으로 거의 안 움직였다.
DS 는 구간의 절반이 30초 한 칸이라 앞뒤를 봐도 얻을 것이 적다.

### 6.4 결론

```
                    macro-F1    W      LS     DS      R
신경망 조각 하나      0.791   0.920  0.814  0.706  0.723
신경망 앞뒤 4.5분     0.826   0.929  0.850  0.720  0.805
catboost             0.839   0.925  0.873  0.805  0.753
```

**전체는 부스팅이 1.3%p 앞선다. 그런데 REM 만은 신경망이 5.2%p 앞선다.**
평균은 흐름의 모양을 지우고 순서를 훑는 쪽은 그것을 남긴다.
반대로 DS 는 부스팅이 8.5%p 앞선다. 짧게 스치는 구간에서는 평균이 잡음을 줄여준다.

**두 방식이 서로 다른 단계를 잘한다.**

**남은 한계**: 학습 회차를 검증용 피험자로 고르는 것으로 바꿨지만,
부스팅에는 그런 절차 자체가 없어 완전히 같은 조건은 아니다.

## 7. 실시간 판정

### 7.1 왜 따로 만들었나

학습은 밤 전체를 한꺼번에 놓고 계산하지만 실제 기기는 조각을 하나씩 보낸다.
**같은 답이 나오도록 조각 단위로 다시 계산하는 경로**를 만들었다.

**학습과 서빙이 특징 계산 코드를 공유한다.** 계산을 두 벌 두면 두 값이 조용히 갈라진다.
그것을 구조로 막았다.

### 7.2 처음에 0% 일치했다

한꺼번에 낸 판정과 조각씩 낸 판정을 대조했더니 **하나도 안 맞았다.** 원인이 네 개였다.

1. 조각 번호 기준이 달랐다
2. 과거 2분 평균을 판정 대상이 아니라 가장 최근 조각 기준으로 계산했다.
   판정 대상보다 3.5분 뒤의 값을 쓴 셈이다
3. 필터를 조각 하나에만 걸어 양끝이 왜곡됐다. 앞뒤 조각을 이어 붙여 걸고
   가운데만 꺼내 쓰도록 고쳤다. 특징 오차가 0.0377 에서 0.0000004 로 줄었다
4. 비교 대상이 틀렸다. 학습 중 저장한 예측은 데이터를 나눠 학습한 다른 모델이 낸 것이다

**전부 고친 뒤 839조각 전부 일치했다.** 이 도구가 `replay` 다.

### 7.3 지연

**9조각, 4.5분.** 창의 절반 7조각에 필터 여유분 2조각이 더해진다.

한동안 3.5분으로 보고하고 있었다. **필터 여유분을 세지 않았다.**
지연을 계산하는 자리를 한곳으로 모으고 검사로 고정했다.

### 7.4 속도

```
특징 계산   11.7 ms
추론         1.7 ms
합계        13.4 ms       30초 예산의 0.045%
```

### 7.5 지연 예산

```
0분 허용    0.8297 *   열 193개
4분 이상    0.8381 *   열 289개
```

**즉시 답하면 0.84%p 를 잃는다.** 4분만 기다리면 무제한과 같아진다.
앞뒤 평균이 앞으로 3.5분을 보므로 그 이상 기다려도 새로 쓸 수 있는 특징이 없다.

## 8. 배포

### 8.1 모델 저장 형식

**라이브러리 자체 형식을 쓴다.** 피클은 라이브러리 버전이 바뀌면 읽지 못한다.

함께 저장하는 것: 열 이름과 순서, 전처리 설정, 성능과 한계를 적은 설명서.
**모델 파일만으로는 어떤 순서로 값을 넣어야 하는지 알 수 없다.**
순서가 어긋나면 오류 없이 엉뚱한 답이 나온다.

### 8.2 API

FastAPI 와 uvicorn. 기기가 30초마다 조각 하나를 보내면 준비되는 대로 판정을 돌려준다.

**표준과 다른 점이 하나 있다.** 보통 추론 서버는 상태가 없어서 아무 서버나 받으면 된다.
우리는 판정에 앞뒤 조각이 필요해 **그 기기가 지금까지 보낸 것을 기억해야 한다.**
그래서 세션이 있고, 같은 기기의 요청이 같은 서버로 가야 한다.

### 8.3 저장 계층

종류마다 크기가 크게 달라 저장하는 곳을 나눴다.

```
판정 결과   하룻밤 0.12MB    조회가 잦고 작다        SQLite
특징 표     하룻밤 1.4MB     통째로 읽고 쓴다        parquet
원신호      하룻밤 28.8MB    판정의 240배           기본으로 저장 안 함
세션 상태   수백 KB          다시 떴을 때 이어가려고  20조각마다 저장
```

같은 조각이 다시 와도 행이 늘지 않도록 세션과 조각 번호를 기본키로 뒀다.
**어느 모델이 언제 무엇을 판정했는지**를 감사 기록에 남긴다.

### 8.4 경량화는 이 구조에서 중요하지 않다

처음에 "저비용" 을 모델 크기로 설명했는데 **그것은 온디바이스 추론일 때의 이야기다.**
서버에서 도는 이상 2.7MB 든 500MB 든 상관없고 추론 2ms 든 200ms 든
30초 예산의 1% 미만이다.

**실제 제약은 세션 메모리다.**

```
세션 하나      199 MB      하룻밤 기준
동시 1000명    199 GB      서버가 못 버틴다
```

판정하려면 그 사람의 지난 값 분포를 들고 있어야 해서 조각이 쌓일수록 메모리가 는다.
**여기가 손봐야 할 곳이다.** 중앙값과 분위수만 필요하므로 근사 알고리즘으로 바꾸면
조각 수와 무관하게 일정한 크기로 만들 수 있다.

부스팅을 고른 진짜 이유는 두 개다. **성능이 더 좋고, GPU 가 필요 없어 서버 비용이 낮다.**
모델 크기는 이유가 아니었다.

## 9. 재현성 장치

### 9.1 설정 해시

산출물 이름을 설정의 해시로 정한다. 같은 설정이면 같은 이름이라 다시 만들지 않는다.

**여기서 사고가 날 뻔했다.** 밴드파워 계산을 고쳤는데 설정은 그대로였다.
이름이 같으니 **옛 파일을 그대로 쓰려고 했다.** `--overwrite` 를 손으로 붙여서 넘어갔는데,
안 붙였으면 고친 줄 알고 옛 값으로 계속 실험했을 것이다.

**고친 방법**: 특징 값에 영향을 주는 파일들의 내용으로 지문을 만들어 기록에 함께 남긴다.
다음에 돌릴 때 지문이 다르면 조용히 건너뛰지 않고 멈춰서 알려준다.

**이름에는 넣지 않았다.** 이름까지 지문을 넣으면 주석 한 줄만 고쳐도 3GB 를 다시 만들어야 한다.

### 9.2 커밋 훅

커밋할 때마다 서식 검사, 문법 검사, 시험이 자동으로 돌고 실패하면 커밋이 거부된다.

**손으로 사슬을 엮으면 줄바꿈에서 끊긴다.** 셸에서 줄바꿈은 세미콜론과 같아
앞 명령이 실패해도 다음 줄이 실행된다. 실제로 이 실수로 깨진 코드가 두 번 커밋됐다.

**한동안 `scripts` 가 검사 범위 밖이었다.** 그 안에 오류 188개가 통과하고 있었다.
범위에 넣었다.

### 9.3 시험을 어디에 쓰나

**에러 없이 성능만 나빠지는 것**만 골라 담는다.

```
시끄럽게 죽는다   모양 불일치, 파일 없음    실행하면 안다
조용히 틀린다     시간축 부호, 채점 범위    시험으로만 잡힌다
```

실제로 `shift` 의 부호 버그는 다른 버그 때문에 실행이 멈춰서 우연히 발견됐다.
그게 없었으면 실험을 다 돌린 뒤에야 이상하다는 걸 알았을 것이다.

## 10. 찾아낸 결함

### 10.1 상대 밴드파워의 합이 1이 아니었다

여섯 대역이 0.4~30Hz 를 빈틈없이 나누고 분모도 같은 구간인데
**합이 평균 0.906, 최소 0.577** 이었다.

사다리꼴 공식으로 구간을 나눠 적분하면 **구간 경계에 걸친 조각이 어느 쪽에도
들어가지 않는다.** 경계가 다섯 개라 그만큼 빠진다.

**단순한 오차가 아니다.** 세기가 몰린 자리를 자를수록 많이 잃는데,
델타파가 강한 조각일수록 1Hz 경계에서 크게 잃는다.
**재려는 대상과 같은 방향으로 왜곡된다.**

직사각형 합으로 바꿔 지금은 1.000000 이다. 1Hz, 10Hz, 20Hz 신호로 검사를 붙였다.

### 10.2 의존성 하나가 목록에 없었다

`antropy` 가 특징 계산에 쓰이는데 `pyproject.toml` 에 없었다. 서버에는 예전에
깔려 있어서 드러나지 않았다. **클론해서 설치한 사람은 특징 추출이 안 된다.**

**도커로 빌드하지 않았으면 못 찾았다.** 깨끗한 환경에서 설치해봐야 드러난다.

### 10.3 모르는 모델 종류를 조용히 다른 것으로 읽었다

`if/elif/else` 로 되어 있어 모르는 종류가 오면 lightgbm 으로 읽으려 들었다.
레지스트리로 바꾸고 모르는 이름은 예외를 내도록 했다.

### 10.4 이름을 잘못 붙인 특징

이마와 뒤통수의 저주파 진폭 차이를 "안구운동 대리 지표" 라고 불렀다.
측정해보니 **REM 은 거의 못 가르고(0.453) 깊은 잠을 가장 잘 갈랐다(0.966).**

**깊은 잠의 느린파도 이마에서 크게 나타나기 때문이다.** 지금 이 지표는
안구운동이 아니라 이마 쪽 저주파 우세도이고 사실상 느린파 특징이다. 이름을 바꿨다.

진짜 안구운동을 가르려면 **위상**을 봐야 한다. 뇌의 느린파는 두 채널이 같이 움직이고
안구운동은 이마만 움직인다. 진폭 차이 대신 상관관계를 보면 갈릴 수 있다. 아직 확인 안 했다.

## 11. 지금 특징을 추가하는 이유

### 11.1 오차 분석이 가리킨 곳

```
단계   F1      만점까지
W      0.925    7.5%p
LS     0.873   12.7%p
DS     0.805   19.5%p
R      0.753   24.7%p
```

macro-F1 을 3%p 올리려면 네 개를 합쳐 12%p 를 벌어야 한다.
**여지가 R 과 DS 에 몰려 있다.**

**R 과 DS 는 실패 이유가 다르다.**

```
가장자리에서   DS      R
0칸          0.559  0.470
8칸          0.927  0.760
```

DS 는 구간 안쪽으로 가면 회복하는데 R 은 멈춘다. 원인은 구간 길이였다.
**DS 는 구간의 53%가 30초 한 칸이고, R 은 중앙값이 10칸이다.**
DS 오답의 절반이 3칸 이하 구간에서 나온다.

**R 은 확신하며 틀린다.** 틀린 REM 의 34.8% 가 확신도 0.8 이상이다.
헷갈려서 찍는 것이 아니라 특징이 그 구간을 LS 처럼 보이게 만들고 있다.

확신하며 틀린 REM 을 특징 공간에서 보면 **이미 LS 자리에 있다.**

```
                      맞힌 R    틀린 R    진짜 LS
Pz-Oz 진폭 표준편차    -0.242   -0.080    +0.002
```

**지금 특징으로는 되찾을 수 없다.** 다른 원리로 가르는 특징이 필요하다.

### 11.2 무엇이 빠졌나

REM 과 얕은 잠을 가르는 결정적 신호는 **수면방추**다. 11~16Hz 진동이 0.5~2초 동안
방추 모양으로 나타나는 사건이고, 판독 기준에 "N2 로 판정하려면 방추나 K복합체가
하나 이상 있어야 한다" 고 적혀 있다. **REM 에는 없다.**

그런데 우리는 **시그마 대역의 30초 평균 세기**만 쓴다.
**1초짜리 방추 하나는 30분의 1로 희석된다.**

측정하니 이렇다.

```
              REM     얕은 잠
방추 개수      0.10     4.12
0개인 비율    94.8%    20.5%
```

**REM 조각의 95%는 방추가 하나도 없다.**

```
                R vs LS AUC   0.5 에서 거리
시그마 중앙값       0.239        0.261      ← 지금 쓰는 것
시그마 평균         0.201        0.299
방추 개수           0.126        0.374
```

AUC 는 0.5 에서 멀수록 잘 가른다. **사건으로 세면 평균으로 재는 것보다 훨씬 강하다.**

### 11.3 우리 처리가 신호를 뭉개고 있었다

주파수 분석에서 30초를 5초짜리 6조각으로 나눠 **중앙값**으로 합친다.
순간적인 잡음이 결과를 끌고 가지 못하게 하려는 것이었는데,
**방추도 순간적인 사건이라 같이 버려진다.**

```
              방추 있음   방추 없음    차이
중앙값         0.0459     0.0177    +0.0283
평균           0.0533     0.0176    +0.0357
```

**중앙값이 방추의 기여를 20% 정도 깎는다.** 잡음을 막으려던 장치가 신호도 막고 있었다.

### 11.4 신경망도 같은 실수를 하고 있다

CNN 의 마지막이 `AdaptiveAvgPool1d(8)` 이다. 30초를 8칸으로 평균하니
한 칸이 3.75초다. **1초짜리 방추가 3.75초로 희석된다.**
우리 특징이 30분의 1로 희석하는 것보다는 낫지만 같은 실수를 규모만 줄여서 하고 있다.

**이것이 부스팅과 신경망이 같이 좋아져야 하는 이유다.**
한쪽만 좋아지면 진단이 부분적으로 틀린 것이다.

### 11.5 실시간 제약

방추 검출 자체는 조각 하나 안에서 끝나 **추가 지연이 없다.**

문제는 문턱이었다. 처음에는 밤 전체의 상위 8% 를 썼는데 **밤이 끝나야 알 수 있는 값**이다.
절대값으로 정할 수도 없다. **사람마다 진폭이 몇 배씩 다르다.**
같은 얕은 잠인데 장비가 다르면 15.3µV 와 23.8µV 로 나온다.

지나온 조각들로만 문턱을 정하도록 바꾸고 성능이 유지되는지 확인했다.

```
              R vs LS AUC
밤 전체 문턱     0.127
과거만 문턱      0.127      ← 같다
```

채널은 이마가 낫다. 방추는 머리 중앙에서 가장 크게 잡히는데 `Fpz-Cz` 가 Cz 를 포함한다.

### 11.6 순서

하나씩 넣고 매번 10묶음으로 재서 **직전 대비 몇 %p 인지**와
**새 특징이 중요도에서 몇 위인지**를 본다.

```
0  기준선
1  주파수 분석을 중앙값에서 평균으로     계산 공짜
2  5초 조각 6개의 최댓값과 최솟값 추가   거의 공짜
3  방추 개수와 지속시간 추가            가장 강함
4  신경망의 마지막 평균을 최댓값으로     코드 한 줄
```

**최댓값이 방추 검출을 대신하지는 못한다.** 잡음에 그대로 열리고,
방추가 1개든 4개든 최댓값은 비슷해서 **개수 정보가 사라진다.**
실제로 얕은 잠은 평균 4개, REM 은 0.1개라 개수 자체가 정보다.

### 11.7 후처리는 왜 나중인가

저장해 둔 확률만으로 계산되는 후처리가 두 개 있다. 상태 전이 모델과 클래스별 임계값이다.
예상 2~4%p 이고 학습이 필요 없다.

```
전체 195,441 조각 중 틀린 것 25,070 (12.8%)
  정답이 2등이었던 것        21,645  (86.3%)
  앞뒤는 맞고 가운데만 틀림   5,565  (22.2%)
```

**틀린 것의 86%는 정답이 2등이다.** 고르는 규칙만 바꿔도 되찾을 후보다.

**그래도 특징을 먼저 고치기로 했다.** 후처리는 증상을 덮는 것이고,
**틀린 것의 13.7%는 정답이 3등 이하라 후처리로 못 살린다.**
그 부분은 특징을 고쳐야 한다.

## 12. 아직 안 한 것

- 피험자별 성능이 낮은 것이 진짜 못 읽는 것인지, macro-F1 이 희귀 클래스에
  가혹한 것인지 안 갈랐다. 정확도와 kappa 로도 재서 비교해야 한다
- 안구운동을 위상으로 가르는 방법을 확인하지 않았다
- 7.5분 평활이 짧은 DS 를 뭉개는지 무문맥 학습과 비교하지 않았다
- 세션 메모리를 일정하게 만드는 근사 알고리즘
- 서버를 여러 대로 늘렸을 때의 세션 배정
- 원신호를 저장하는 경로
