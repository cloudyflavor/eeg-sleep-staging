# 전처리 제안서

작성일 2026-08-25. `08-preprocessing-design.md`의 선택지에 대한 **구체적 제안**.

**전제**: EDFX Sleep-Cassette 단독 / Fpz-Cz + Pz-Oz / 4-class / 100 Hz / 피험자 단위 CV.

---

## 0. 설계 원칙 — 이게 나머지 선택을 다 결정합니다

> **되돌릴 수 없는 처리를 중간 산출물에 굽지 않는다.**

전처리를 **2단계**로 나눕니다.

```
[1단계] EDF ──────→ 에포크 npz        정보를 잃지 않는 처리만
                                       (읽기·에포크화·라벨링·절단)
                        ↓
[2단계] npz ──────→ 특징 parquet      정보를 잃는 처리는 전부 여기
                                       (필터·정규화·집계)
```

**왜 이렇게 나누나.**

필터를 1단계에 구워버리면 **"필터 없음 vs 영위상 vs 인과"를 비교하려면 EDF를 다시 파싱해야** 합니다. 153개 파일 전체를요.
필터를 2단계에 두면 npz를 그대로 두고 설정만 바꿔서 다시 돌리면 됩니다.

우리는 **비교 실험이 결과물**이므로, 비교 대상이 되는 처리는 전부 뒤쪽에 있어야 합니다.

**레퍼런스 비교**: DeepSleepNet과 TinySleepNet은 1단계만 있고 필터를 아예 안 겁니다(원신호를 그대로 CNN에 넣음).
sleep-linear은 노트북 하나에서 전부 처리해서 중간 산출물이 특징 parquet 하나뿐입니다 — 필터를 바꾸려면 전부 다시 돌려야 합니다.
U-Time은 `ut preprocess`로 스케일링·QC·리샘플링을 H5에 구워버리는 옵션이 있는데, **그래서 그걸 바꾸려면 재생성이 필요합니다.**

## S1. EDF 리더 — **MNE-Python**

| | MNE | pyedflib |
|---|---|---|
| 주석(hypnogram) 읽기 | **내장** (`read_annotations`) | 별도 처리 필요 |
| 에포크화 | `events_from_annotations` + `Epochs` | **레코드 reshape로 공짜** |
| 속도 | 느림 | **빠름** |
| 서버 설치 상태 | **이미 있음 (1.12.1)** | **없음** |
| 단위 처리 | 자동 (볼트로 통일) | 수동 |

**MNE를 고르는 이유 네 가지.**

1. **이미 설치돼 있습니다.** pyedflib는 없고, 서버 설치 허가를 아직 못 받았습니다. 지금 당장 진행 가능한 게 MNE뿐입니다.
2. **hypnogram 파싱이 한 줄입니다.** EDF+ 주석 포맷을 직접 파싱하는 건 성가십니다 — DeepSleepNet은 그것 때문에 `dhedfreader.py`를 직접 만들어 번들했습니다.
3. **YASA가 MNE Raw 객체를 입력으로 받습니다.** 나중에 YASA를 비교군으로 돌릴 때 그대로 연결됩니다. pyedflib면 변환 계층을 하나 더 만들어야 합니다.
4. **확장성.** 나중에 ST나 HMC를 붙이거나 리샘플링할 때 코드를 갈아엎지 않아도 됩니다.

**트레이드오프 — 인정할 것.** MNE는 느리고 무겁습니다. pyedflib는 EDF의 레코드 구조(EDFX는 30초 레코드)를 그대로 reshape해서 에포크를 공짜로 얻습니다. TinySleepNet이 그래서 DeepSleepNet보다 코드가 훨씬 깔끔합니다.
**다만 153개 파일 규모에서는 속도가 병목이 아닙니다.** 수만 개 파일이면 pyedflib를 골랐을 겁니다.

> **레퍼런스**: MNE — YASA, DeepSleepNet, U-Time / pyedflib — TinySleepNet, sleep-linear

## S2. 파일 짝짓기 — **앞 7자 정규식 + 시작시각 검증**

```
SC4001E0-PSG.edf         ┐
SC4001EC-Hypnogram.edf   ┘  앞 7자 "SC4001E" 공통, 8번째만 다름
```

```python
stem = psg_path.stem[:7]                      # "SC4001E"
hyp = next(cassette_dir.glob(f"{stem}*-Hypnogram.edf"))
assert raw.info["meas_date"] == annotations_start   # 시작시각 일치 검증
```

**왜 이렇게.** DeepSleepNet은 두 목록을 정렬하고 **인덱스 i끼리** 짝짓습니다.
파일이 하나 빠지면 **이후 전부 어긋나는데 조용히 진행됩니다.** 안전장치가 시작시각 assert 하나뿐입니다.

정규식 매칭 + assert는 비용이 사실상 0이고, **틀리면 시끄럽게 죽습니다.** 조용히 틀린 결과를 내는 것보다 낫습니다.

> **레퍼런스**: TinySleepNet(`data.py::get_subject_files`), U-Time(`psg_regex`/`hyp_regex` YAML)

## S3. 라벨 매핑 — **4-class + UNKNOWN 구분 기록**

```python
LABEL_MAP = {
    "Sleep stage W": 0,                                # W
    "Sleep stage 1": 1, "Sleep stage 2": 1,            # LS
    "Sleep stage 3": 2, "Sleep stage 4": 2,            # DS
    "Sleep stage R": 3,                                # R
}
DROP = {"Sleep stage ?": "unknown", "Movement time": "movement"}
```

**`?`와 `Movement time`을 구분해서 세고, 로그에 남긴 뒤 제거합니다.**

**왜 구분하나.** DeepSleepNet은 둘 다 `UNKNOWN=5`로 묶습니다. TinySleepNet은 `?=6`, `Movement=5`로 나눕니다.
구분해두면 나중에 **"판독 불가 구간이 많은 녹음이 성능이 나쁜가"** 같은 분석을 할 수 있습니다. 묶어버리면 못 합니다.

**실측 (2026-08-26, 153개 전수).** 앞서 "297건"이라고 적었던 건 **주석 건수**였다.
주석 하나가 여러 에포크를 덮으므로 에포크 수는 다르다.

| | 에포크 |
|---|---:|
| `Sleep stage ?` (전체) | 25,047 |
| ┗ 신호가 끝난 뒤 구간 | 23,712 |
| ┗ **신호 안에 있는 것** | **1,335** |
| `Movement time` | 128 |

`Sleep stage ?` 의 대부분은 **녹음이 끝난 뒤에도 주석만 이어진 구간**이다.
판독할 신호가 아예 없는 자리라 채점자가 `?` 로 남긴 것이고, 애초에 처리 대상이 아니다.
신호 안에 실제로 있는 건 1,463개 = **전체의 0.35 %**.

**왜 마스킹 안 하나.** U-Time은 제거 대신 손실에서 마스킹합니다. **부스팅 트리는 행 단위라 마스킹 개념이 없습니다.** 우리 모델에 안 맞습니다.

## S4. 제거 순서 — **에포크화 → wake 절단 → UNKNOWN 제거**

TinySleepNet 순서입니다.

**왜 이 순서.** DeepSleepNet은 UNKNOWN을 **샘플 단위**로 먼저 지웁니다. 그러면 신호가 이어붙여지면서 **에포크 경계가 원본과 어긋나고**, 인덱스 계산이 복잡해집니다(그 코드가 지저분한 이유입니다).

에포크 단위로 처리하면 **경계가 항상 원본 30초 격자와 일치**합니다.

**부작용 하나 — 반드시 처리해야 합니다.** 중간의 에포크를 지우면 **시간축에 구멍**이 생깁니다.
나중에 이동평균이나 이웃 참조를 할 때 "1분 전"이 실제로는 3분 전일 수 있습니다.

→ **원본 에포크 번호(`epoch_idx`)를 같이 저장합니다.** 그러면 2단계에서 구멍을 알아채고 처리할 수 있습니다.

## S5. Wake 절단 — **±60 에포크, 원본도 같이 보존**

```python
w_edge = 60                                   # 30분 = 60 에포크
nw = np.nonzero(labels != W)[0]
lo, hi = max(0, nw[0] - w_edge), min(len(labels), nw[-1] + w_edge + 1)
```

DeepSleepNet `prepare_physionet.py`의 `w_edge_mins = 30` × 2와 동일합니다.

**왜 자르나.** 안 자르면 W가 68.8%라 **다수클래스만 찍어도 68.8%**가 나옵니다. 잘라내는 건 대부분 "낮에 멀쩡히 깨어 있는" 구간이라 임상적으로 무의미합니다.

**약점을 알고 갑니다.** 자를 위치를 정하려고 **정답 라벨을 봅니다.** 배포 시점엔 라벨이 없으니 엄밀히는 재현 불가능한 처리입니다.
방어: (a) 벤치마크 관행, (b) 잘리는 건 쉬운 에포크뿐, (c) 점수가 **내려가는** 방향(46.4% 베이스라인).

**제안: 절단 인덱스만 저장하고 신호는 전체를 남깁니다.**

```python
np.savez(..., data=all_epochs, labels=all_labels,
         crop_lo=lo, crop_hi=hi)     # 자르지 않고 경계만 기록
```

그러면 **"절단 vs 미절단"을 npz 재생성 없이 2단계에서 비교**할 수 있습니다. §0 원칙 그대로입니다.

> 대안으로 `SC-subjects.xls`의 `LightsOff`를 쓰면 **시작점은 라벨 없이** 정할 수 있습니다.
> 다만 `LightsOn`이 없어서 끝점은 여전히 라벨이 필요합니다. **부가 실험으로 남깁니다.**

## S6. 필터 — **1단계에서는 걸지 않습니다**

**이유 셋.**

1. **EDFX는 하드웨어에서 이미 필터링됐습니다** (HP 0.5Hz / LP 100Hz). 추가 필터가 필요한지 자체가 열린 질문입니다.
2. **대역파워를 Welch PSD로 내면 시간영역 밴드패스가 불필요합니다.** YASA와 sleep-linear 둘 다 PSD로 냅니다.
3. **§0 원칙** — 필터는 정보를 잃는 처리라 A/B 대상입니다. 1단계에 구우면 비교를 못 합니다.

**2단계에서 세 가지를 비교합니다**: 필터 없음 / `sosfiltfilt` 영위상 0.4–30Hz / `lfilter` 인과 0.4–30Hz.

> **레퍼런스**: DeepSleepNet 필터 없음 / YASA FIR 영위상 0.4–30Hz / sleep-linear Butterworth 5차 **인과** 0.4–30Hz
> — 세 레포가 세 가지를 다 씁니다. **정답이 정해져 있지 않다는 뜻**이므로 우리가 재는 게 맞습니다.

## S7. 아티팩트 — **제거하지 않고 지표만 저장**

에포크별로 아래를 계산해 함께 저장합니다.

| 지표 | 용도 |
|---|---|
| `ptp` (peak-to-peak) | 진폭 이상 |
| `std` | 진폭 이상 |
| `flat_ratio` (연속 동일값 비율) | 전극 탈락 |

**왜 제거하지 않나.**

- **에포크를 제거하면 평가 대상이 달라져 비교가 깨집니다.** 어려운 에포크만 골라 버리면 점수가 부당하게 오릅니다.
- **YASA는 수면 단계 분류 경로에서 아티팩트 제거를 아예 안 합니다.** 대신 **Welch를 평균이 아니라 중앙값으로** 집계해서 견딥니다. 문제를 제거가 아니라 **강건한 통계량**으로 푸는 접근입니다.
- 우리 기존 500 µV 임계값은 **EDFX에서 검출률 0.00%** 였습니다 — 임계값 하나로 두 데이터셋을 다루려던 게 실패한 사례입니다.

지표를 저장해두면 나중에 **"아티팩트 많은 에포크에서 성능이 떨어지나"** 를 분석할 수 있습니다.

> **레퍼런스**: YASA(제거 안 함, 중앙값 Welch) / U-Time(`clip_noisy_values`, 전역 IQR×20 클리핑)

## S8. 저장 — **녹음당 npz 하나**

```python
np.savez_compressed(f"{subject}_{night}.npz",
    data       = epochs,        # (n_ep, 2, 3000) float32, 볼트
    labels     = labels,        # (n_ep,) int8  0=W 1=LS 2=DS 3=R
    epoch_idx  = epoch_idx,     # (n_ep,) int32  원본 에포크 번호 (구멍 추적)
    crop_lo    = lo, crop_hi = hi,
    ptp        = ptp,           # (n_ep, 2) float32
    std        = std,           # (n_ep, 2)
    flat_ratio = flat,          # (n_ep, 2)
    subject    = "SC400", night = 1, sfreq = 100.0,
    ch_names   = ["EEG Fpz-Cz", "EEG Pz-Oz"],
    config_hash= "...",         # 멱등 재개용
)
```

**크기 추정**: 195,479 에포크 × 2채널 × 3000 샘플 × 4바이트 = **약 4.7 GB**.

현재 서버의 `data/processed/`가 46GB인 이유는 **채널 3개 + 보조채널 + 절단 안 함**이기 때문입니다.
**EEG 2채널만 남기면 10분의 1로 줄어듭니다.** 디스크 여유가 103GB뿐이라 이게 중요합니다.

**왜 녹음당 파일인가.**

- **병렬화가 자명합니다** — 프로세스마다 다른 파일을 쓰니 동시 쓰기 충돌이 없습니다
- **부분 재빌드**가 됩니다 — 파일 하나가 깨져도 그것만 다시
- **피험자 단위 분할이 쉽습니다** — 파일명이 곧 피험자 키

**왜 HDF5 하나가 아닌가.** U-Time이 그렇게 하는데, 자기 코드에 **"HDF5가 스레드 안전하게 컴파일돼야 한다"** 는 경고를 달아뒀습니다. 동시 쓰기가 골칫거리입니다. 우리 규모에선 얻는 게 없습니다.

> **레퍼런스**: 녹음당 파일 — DeepSleepNet, TinySleepNet, U-Time, SLEEPYLAND **전부**

## S9. 멱등 재개 — **설정 해시로 건너뛰기**

```python
if out_path.exists() and stored_hash == current_config_hash and not overwrite:
    log.info("skip (unchanged)"); continue
```

**왜.** DeepSleepNet과 TinySleepNet은 **시작할 때 출력 디렉터리를 `shutil.rmtree`** 합니다.
153개를 돌리다 100번째에서 끊기면 **처음부터**입니다.

설정 해시를 비교하면 **설정이 바뀌었을 때만 다시 계산**됩니다. 15줄이면 됩니다.

# 요약

| # | 결정 | 핵심 근거 |
|---|---|---|
| **0** | **2단계 분리** (에포크 npz → 특징 parquet) | **A/B 대상 처리를 뒤쪽에.** 비교가 결과물이므로 |
| S1 | **MNE** | 이미 설치됨 + 주석 파싱 내장 + YASA 연결 |
| S2 | 앞 7자 정규식 + 시작시각 assert | 정렬 인덱스는 조용히 어긋남 |
| S3 | 4-class, `?`·Movement 구분 기록 후 제거 | 트리 모델은 마스킹 불가 |
| S4 | 에포크화 → 절단 → UNKNOWN 제거 | 에포크 경계가 원본과 일치 |
| S5 | ±60 에포크, **경계만 기록하고 신호는 보존** | 절단 여부를 2단계에서 비교 |
| S6 | **1단계에선 필터 안 걸음** | 레퍼런스 3곳이 셋 다 다름 = 재봐야 함 |
| S7 | 제거 안 함, 지표만 저장 | 제거하면 평가 대상이 달라짐 |
| S8 | 녹음당 npz (약 4.7GB) | 병렬화·부분재빌드·분할 |
| S9 | 설정 해시 멱등 재개 | rmtree는 153개 돌리다 끊기면 처음부터 |
| S10 | 녹음별 감사 로그 | 추적 가능성 |

**S1(MNE)과 S8(npz)만 되돌리기 어렵습니다.** 나머지는 설정으로 뺄 수 있습니다.
