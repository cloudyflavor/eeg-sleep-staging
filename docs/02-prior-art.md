# 선행 연구 — 문헌과 레포

**이 접근이 유효한가**, **어디까지가 현실적인 성능인가**, **남의 코드에서 무엇을 가져올 것인가**.

조사 기간 2026-08-03 ~ 08-25. 이후 문헌 조사는 종료했다 — 방향을 정하는 데 필요한 만큼은 확보했다고 판단했다.
개별 결정에 이 근거들이 어떻게 쓰였는지는 [`04-design-stage1.md`](04-design-stage1.md)·[`05-design-stage2.md`](05-design-stage2.md).

---

## 1. 특징 + 부스팅은 죽은 길이 아니다

**Van der Donckt et al. (2023), "Do not sleep on traditional machine learning"**
*Biomed. Signal Process. Control* 81:104429 · [DOI](https://doi.org/10.1016/j.bspc.2022.104429) · 코드 [predict-idlab/sleep-linear](https://github.com/predict-idlab/sleep-linear)

수작업 특징 1,048개 + **CatBoost** 로, **피험자 단위 CV 라는 정직한 프로토콜에서 DeepSleepNet 을 이겼다.**
하이퍼파라미터 튜닝도, 특징 선택도 하지 않았다.

| 데이터셋 | 프로토콜 | ACC | MF1 |
|---|---|---:|---:|
| Sleep-EDF SC-20 | LOSO 20-fold | 0.866 | **0.810** |
| Sleep-EDF SC-78 | 10-fold 피험자 그룹 | 0.831 | 0.775 |
| MASS SS3 | 10-fold 피험자 그룹 | 0.867 | **0.817** |

같은 프로토콜의 딥러닝: DeepSleepNet SC-20 MF1 **0.769** / TinySleepNet 0.805 / XSleepNet2 0.809.

> 단서: 특징 1,048개(기본 131 × 윈도 3종 × 앞뒤 2에포크)에 EEG 2채널 + EOG + EMG 다.
> 우리는 EEG 2채널뿐이다.

**교차 검증된 지점**: 이 논문이 보고한 30분 절단 후 W 비율 SC-78 **33.6 %** 가
우리 실측 **33.74 %** 와 일치한다 → 우리 전처리가 표준 관행과 맞다.

## 2. 현실적인 성능 범위

정직한 피험자 단위 평가에서 5-class 기준 **ACC 83–87 %, MF1 0.77–0.82, κ 0.77–0.82** 가 특징 기반의 실제 범위다.

| | 규모 | 결과 |
|---|---|---|
| **YASA** (Vallat & Walker 2021, *eLife* 10:e70092 · [DOI](https://doi.org/10.7554/eLife.70092)) | 3,163박 학습 → 585박 held-out | 중앙값 ACC **87.46 %**, κ 0.819. 외부 데이터셋(DOD-H/O) 84.3–86.6 %. 전문가 5인 합의 대비 **개별 인간 채점자와 통계적으로 구분되지 않음** |
| **Sun et al. 2017** (*Sleep* 40(10):zsx139 · [PMID](https://pubmed.ncbi.nlm.nih.gov/29029305/)) | MGH 임상 PSG 2,000박, 환자 단위 분할 | **κ = 0.68** |

Sun 2017 이 현실 점검용으로 가장 중요하다. **큐레이션된 연구용 코호트(κ 0.82)와 실제 임상 데이터의 격차**를 보여준다.

### 평가 프로토콜이 점수를 8.7 %p 움직인다

**Memar & Faradji (2018)**, *IEEE TNSRE* 26(1):84–95 · [DOI](https://doi.org/10.1109/TNSRE.2017.2776149)
같은 데이터·같은 특징·같은 분류기(Random Forest)로 두 프로토콜을 모두 보고한다.

| 프로토콜 | 정확도 |
|---|---:|
| 에포크 단위 nested 5-fold CV | 95.31 % |
| **피험자 단위 CV** | **86.64 %** |
| 차이 | **8.7 %p** |

**이게 우리가 피험자 단위 CV 를 쓰는 이유다.** 같은 사람의 인접 에포크가 학습과 평가로 갈리면 점수가 부풀려진다.

부풀림 기전 세 가지가 문헌에 정리돼 있다.

| 기전 | 전형적 부풀림 | 탐지법 |
|---|---:|---|
| 에포크/녹음 단위 CV | +7~9 %p | "10-fold CV" 만 적고 피험자 그룹핑 언급이 없다 |
| **분할 전** 클래스 리샘플링 | +9.6 %p | N1 정확도가 비정상적으로 높다 |
| Wake 미절단 | 큼 (정량화 안 됨) | 절단 규칙 서술이 없고 W F1 이 수상하게 높다 |

> **신뢰성 판별 기준**: Sleep-EDF 에서 N1 F1 이 0.60 을 넘으면 의심하라. YASA 가 0.43 이다.
> 90 %+ 를 주장하는 특징 기반 논문 대부분이 위 셋 중 하나 이상에 해당한다.

## 3. 아키텍처 경쟁은 포화됐다

독립적인 근거 네 개가 같은 방향을 가리킨다.

**(a) 긴 문맥의 효과가 1 %p 미만에서 포화한다** — L-SeqSleepNet ablation (SHHS)

| 문맥 길이 L | ACC | MF1 | 학습(s) |
|---:|---:|---:|---:|
| 100 | 88.1 | 80.7 | 354 |
| 400 | 88.2 | 81.4 | 626 |

4배 늘려도 +0.1 %p. 논문의 진짜 기여는 정확도가 아니라 **비용**이다.

**(b) 트랜스포머를 CNN+BiLSTM 위에 얹어 얻는 게 +0.1 %p** — MultiScaleSleepNet ablation (Sleep-EDFx)

| 구성 | MF1 |
|---|---:|
| CNN | 0.767 |
| **CNN + BiLSTM** | **0.795** |
| + multi-head attention | 0.811 |

**(c) 학습 안 된 무작위 트랜스포머가 거의 같은 성능** — arXiv 2605.09905 (2026).
*"성능 향상의 대부분은 파라미터 학습이 아니라 구조적 귀납 편향에서 온다."*
(절대 수치가 SOTA보다 낮아 백본이 약하다. 상대 비교만 유효.)

**(d) 데이터가 아키텍처를 압도한다** — SLEEPYLAND (*npj Digital Medicine* 9:55, 2026 · [arXiv](https://arxiv.org/html/2506.08574v2)),
24개 데이터셋 30만 시간 벤치마크.
*"자동 수면 단계 분류의 진보는 새로운 모델 구조보다 학습 데이터의 확대와 다양화에서 더 크게 온다."*
*"어떤 구조도 인구통계·임상 지표 편향을 일관되게 줄이지 못한다."*

보강: L-SeqSleepNet 의 Sleep-EDF 성능은 **사전학습만으로 +2.3 %p**(86.3→88.6) 오른다.
이 조사에 나온 어떤 아키텍처 격차보다 크다.

**함의**: 새 구조를 제안하는 방향은 값이 없다. **평가 프로토콜·일반화·배포 가능성**이 남은 각도다.

## 4. N1 이 유일하게 남은 병목

이 계보 전체에서 N1 F1 최고치가 **53.3** 이고 대부분 40대다. 모든 모델의 macro-F1 을 N1 이 끌어내린다.

그런데 **N1 은 구조가 아니라 데이터·손실 개입에 반응한다.**

- SleepEGAN (GAN + 앙상블): SHHS N1 F1 40.5 → **54.1** — arXiv 2307.05362
- 데이터 증강 (*J. Neural Eng.* 2020, [DOI](https://iopscience.iop.org/article/10.1088/1741-2552/abb5be)): 전체 +6 %, **N1 +19 %**

**우리에게 직접 연결되는 지점**: 우리는 4-class 로 N1+N2 를 LS 로 합쳤다.
**가장 어려운 경계를 지운 것**이라 5-class 문헌 수치와 직접 비교할 수 없다. 이 한계는 명시하고 간다.

## 5. 레포 두 개가 각각 반쪽이다 — 여기가 기회

우리와 같은 접근(특징 + 부스팅 트리)을 쓰는 레포를 clone 해서 소스를 읽었다.

| | 패키징·CI·테스트 | 정직한 실험 설계 |
|---|---|---|
| **YASA** | **최상급** | 학습 코드가 아예 다른 레포에 있음 (`yasa_classifier`) |
| **sleep-linear** | **없음** (테스트·CI·린트 전무) | **최상급** (피험자 그룹 CV, 고정 held-out, 누수 방지) |

**둘 다 갖춘 레포가 없다.** 설정 기반 수집 + 특징 캐시 + 그룹 CV + 모델-특징 계약 검증 +
성능 하한 회귀 테스트 + 재현 가능한 배포. 이 조합이 이 프로젝트의 자리다.

> sleep-linear 은 **YASA 위에 지어졌다.** `yasa.bandpower` 를 직접 import 하고
> YASA 의 대역 정의와 antropy 특징 목록을 그대로 쓴다. **이 계열의 뿌리가 YASA 다.**

### YASA 에서 가져온 것

| | 내용 |
|---|---|
| **중앙값 Welch** | `average="median"` — 30초 중 1초에 잡음이 껴도 거의 안 움직인다. **아티팩트 제거를 안 하고 견디는 장치** ([D7](04-design-stage1.md), [D13](05-design-stage2.md)) |
| **원본 + 정규화본 둘 다** | 평활본만 녹음 단위 robust z-score ([D11](05-design-stage2.md)) |
| **특징별 벡터화** | 에포크 루프가 아니라 특징 하나를 전체 에포크에 한 번에. 하룻밤이 몇 초에 끝난다 |
| **모델-특징 이름 계약 검증** | 예측 직전에 학습된 모델이 기대하는 특징 이름과 지금 계산한 이름을 양방향 대조. **train/serve skew 를 막는다** |
| **에포크 자르기 zero-copy** | `as_strided` 로 복사 없이 뷰만. 단 경계 검사를 안 해 잘못 쓰면 메모리를 넘어 읽는다 |

**베끼지 말 것**: 특징 추출·모델 I/O·플로팅·추론이 **550줄짜리 클래스 하나**에 다 들어 있어
특징 단위 테스트가 불가능하다. `joblib` 피클을 wheel 에 담아 라이브러리 버전이 바뀌면 깨진다.

### sleep-linear 에서 가져온 것

| | 내용 |
|---|---|
| **피험자 그룹 CV** | `StratifiedGroupKFold(10, groups=psg_file[:5])` — 2박 녹음을 같은 피험자로 묶는다. 고정 held-out 분리를 **assert 로 검증**까지 한다 |
| **특징 행렬 parquet 캐시** | 특징 추출(느림)과 모델링(빠름)을 분리. 하이퍼파라미터를 바꿀 때마다 EDF 를 다시 읽지 않는다 |
| **기계가 읽는 특징 이름** | `"EEG Fpz-Cz__sdelta__w=30s_shift=-1m"` — 이름을 파싱해 **윈도별·시프트별 중요도를 묶어 분석**한다. 작은 설계인데 분석력이 크게 는다 |
| **시간 문맥 두 방식** | 다중 윈도 + 시프트 컬럼. 녹음 단위 그룹핑해서 밀어 경계를 넘지 않는다 ([D12](05-design-stage2.md)) |

**베끼지 말 것**: 전부 노트북이라 데이터셋별로 같은 파이프라인이 복사-붙여넣기되어 조용히 갈라져 있다.
`pandas.resample().mean()` 리샘플링에 안티에일리어싱이 없다.
메트릭 인자 순서가 바뀐 곳이 있다(`f1_score(preds, y_trues)`) — macro-F1 엔 무해하지만 `classification_report` 에서 precision/recall 이 뒤바뀐다.

## 6. 파이프라인 레포 — 전처리 관행의 출처

| 레포 | 무엇 | 우리가 가져온 것 |
|---|---|---|
| **DeepSleepNet** `prepare_physionet.py` | Sleep-EDF 전처리의 **원본**. 이후 논문 대부분이 여기서 갈라졌다 | wake 절단 `w_edge_mins=30` × 2 = 60 에포크 ([D5](04-design-stage1.md)), 라벨 매핑 ([D3](04-design-stage1.md)) |
| **TinySleepNet** | 같은 레시피, 나은 엔지니어링 | 파일명 기반 짝짓기 ([D2](04-design-stage1.md)), 제거 순서(에포크 단위), 녹음별 로그 ([D10](04-design-stage1.md)) |
| **U-Time / psg-utils** | 다중 코호트를 다루는 기계. YAML 로 데이터셋별 정규식·채널을 선언 | 설정 기반 파이프라인. **단일 HDF5 는 안 가져왔다** — 자기 코드에 "HDF5 가 스레드 안전하게 컴파일돼야 한다"는 경고가 있다 ([D8](04-design-stage1.md)) |
| **SLEEPYLAND** | 벤치마크 하네스. 모델 여러 개를 같은 프로토콜로 돌린다 | 소프트 보팅 앙상블이 개별 모델을 **94.9 % 의 경우에 이겼다** ([07-experiment-plan.md](07-experiment-plan.md)) |

**공통 관행 — 넷 다 동일**

- 녹음당 파일 하나로 저장 (예외 없음)
- 시작할 때 출력 디렉터리를 통째로 지운다 → **우리는 설정 해시 재개로 대체** ([D9](04-design-stage1.md))
- 필터를 안 걸거나(DeepSleepNet·TinySleepNet) 굽는다(U-Time) → **우리는 2단계로 미뤘다** ([D6](04-design-stage1.md))

**필터가 정해져 있지 않다는 증거**

| | 필터 |
|---|---|
| DeepSleepNet | **없음** (원신호를 그대로 CNN 에) |
| YASA | FIR **영위상** 0.4–30 Hz |
| sleep-linear | Butterworth 5차 **인과** 0.4–30 Hz — 그런데 DeepSleepNet 을 이겼다 |

**세 레포가 셋 다 다르다.** 그래서 우리가 잰다 ([D10](05-design-stage2.md)).
