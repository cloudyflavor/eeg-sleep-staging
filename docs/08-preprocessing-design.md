# 전처리 설계 — 결정 지점과 선택지

작성일 2026-08-25. **아직 아무것도 정해지지 않았습니다.** 고르기 위한 문서입니다.

## 이 문서의 범위

**전처리 = 원본 EDF 파일 → "깨끗한 30초 에포크 배열 + 라벨 배열"** 까지.
특징 추출(대역파워·엔트로피 등)은 그 다음 단계고 별도로 설계합니다.

## 확정된 것

| 항목 | 값 |
|---|---|
| 데이터셋 | **EDFX Sleep-Cassette** (153 녹음 / 78명) |
| 채널 | **EEG Fpz-Cz + EEG Pz-Oz** (2채널) |

| 에포크 | 30초 (임상 규약) |
| 샘플링 | 100 Hz (EDFX 원본 그대로, 변환 불필요) |

# D1. EDF 파일을 무엇으로 읽나

EDF는 생체신호 표준 파일 포맷입니다. 헤더(채널명·샘플링레이트 등) + 신호 데이터로 되어 있습니다.

| 선택지 | 특징 | 쓰는 곳 |
|---|---|---|
| **MNE-Python** | 뇌파 분석 표준 라이브러리. 주석(annotation) 처리·필터링·리샘플링이 다 들어있음. 무겁고 느림 | YASA, DeepSleepNet, U-Time |
| **pyedflib** | EDF만 읽는 얇은 라이브러리. 빠름. **레코드 단위로 읽으면 에포크 자르기가 공짜** | TinySleepNet, sleep-linear |

**pyedflib의 "에포크 자르기가 공짜"가 무슨 뜻이냐** — EDF는 내부적으로 이미 일정 길이(EDFX는 30초) 레코드로 나뉘어 저장돼 있습니다. 그대로 읽어서 reshape하면 끝입니다.

```python
signal.reshape(-1, 30 * 100)     # (에포크 수, 3000)
```

MNE로 하면 전체를 이어붙인 뒤 다시 잘라야 해서 인덱스 계산이 복잡해집니다. DeepSleepNet 코드가 그 때문에 지저분합니다.

**트레이드오프**: MNE는 나중에 리샘플링·필터링·다른 데이터셋(HMC) 확장이 쉽습니다. pyedflib는 지금 당장 단순합니다.

> **추천: MNE.** 서버 venv에 이미 설치돼 있고, 나중에 HMC를 붙이거나 리샘플링할 때 다시 안 갈아엎어도 됩니다. 지금의 단순함보다 나중의 확장성이 큽니다.

# D2. PSG 파일과 라벨 파일을 어떻게 짝짓나

EDFX는 신호와 라벨이 **다른 파일**로 되어 있습니다.

```
SC4001E0-PSG.edf         ← 신호
SC4001EC-Hypnogram.edf   ← 라벨
      ↑↑↑↑↑↑
   앞 6자가 공통, 7번째 문자만 다름 (0 vs C)
```

| 선택지 | 방식 | 위험 |
|---|---|---|
| **정렬 인덱스** | 두 목록을 정렬하고 i번째끼리 짝지음 | **파일이 하나 빠지면 이후 전부 어긋남**. 그런데 조용히 진행됨 |
| **파일명 키** | 앞 6자 `SC4001`로 매칭 | 안전 |
| **파일명 키 + assert** | 위 + EDF 헤더의 **녹음 시작시각이 같은지 검증** | 가장 안전 |

**DeepSleepNet이 정렬 인덱스를 씁니다.** 안전장치가 시작시각 assert 하나뿐입니다.
TinySleepNet과 U-Time은 정규식 매칭을 씁니다.

> **추천: 파일명 키 + 시작시각 assert.** 비용이 거의 0이고, 이런 assert가 있다는 것 자체가 코드 품질 신호입니다.

# D3. "Sleep stage ?"와 "Movement time"을 어떻게 하나

EDFX 라벨에는 수면 단계 말고 두 가지가 더 있습니다.

- **`Sleep stage ?`** — 판독자가 판정 못 한 구간
- **`Movement time`** — 몸을 크게 움직여 신호가 못 쓰게 된 구간

| 선택지 | 방식 | 쓰는 곳 |
|---|---|---|
| **둘 다 UNKNOWN으로 묶어 제거** | 가장 단순 | DeepSleepNet |
| **구분해서 남긴 뒤 제거** | 나중에 분석 가능 | TinySleepNet |
| **제거하지 않고 손실에서 마스킹** | 신호는 유지, 학습에서만 제외 | U-Time |

세 번째는 **딥러닝에서만 가능합니다.** 부스팅 트리는 행 단위라 마스킹 개념이 없습니다.

**중요한 부작용**: 중간에 있는 에포크를 제거하면 **시간축에 구멍이 생깁니다.** 나중에 이동평균이나 이웃 참조를 할 때 "1분 전"이 실제로는 3분 전일 수 있습니다.

> **추천: 구분해서 기록하고 제거.** 몇 개가 왜 빠졌는지 로그로 남기고, 제거 후에도 **원래 에포크 번호를 같이 저장**해서 구멍을 나중에 알 수 있게 합니다.

# D4. 제거 순서 — 미묘하지만 결과가 달라집니다

같은 데이터인데 **순서에 따라 남는 에포크가 달라집니다.**

| | 순서 |
|---|---|
| **DeepSleepNet** | UNKNOWN을 **샘플 단위**로 제거 → 에포크 자르기 → wake 절단 |
| **TinySleepNet** | 에포크 자르기 → wake 절단 → UNKNOWN **에포크** 제거 |

**왜 달라지냐** — wake 절단은 "첫 비-W 에포크"를 기준으로 하는데, UNKNOWN을 먼저 지우면 그 "첫 번째"가 바뀔 수 있습니다.

> **추천: TinySleepNet 순서 (에포크 → wake 절단 → UNKNOWN 제거).**
> 샘플 단위 조작이 없어서 코드가 훨씬 단순하고, 에포크 경계가 원본과 정확히 일치합니다.
> **다만 어느 쪽이든 문서에 명시해야 합니다** — 이게 논문 수치가 미묘하게 안 맞는 흔한 이유입니다.

# D5. Wake 절단

EDFX는 **22시간을 통째로** 녹음해서 전체 에포크의 **68.8%가 각성**입니다.

| 선택지 | 결과 | 특징 |
|---|---|---|
| **자르지 않음** | 41.5만 에포크, W 68.8% | 다수클래스 베이스라인이 68.8%. **문헌과 비교 불가** |
| **±60 에포크 (30분)** | 19.5만 에포크, W 33.7% | **표준 관행.** 베이스라인 46.4%로 내려감 |
| lights-off/on 기준 | — | **EDFX엔 해당 주석이 없음** (HMC엔 있음) |

**표준 관행의 실제 코드** (DeepSleepNet `prepare_physionet.py`):

```python
w_edge_mins = 30
nw_idx = np.where(y != W)[0]
start_idx = nw_idx[0]  - (w_edge_mins * 2)   # 60 에포크
end_idx   = nw_idx[-1] + (w_edge_mins * 2)
```

**짚어야 할 약점**: 자를 위치를 정하려고 **정답 라벨을 봅니다.** 실전에서 새 데이터엔 라벨이 없으니 엄밀히는 배포 시 재현 불가능한 처리입니다.

방어 논리 — (a) 벤치마크 관행이라 안 따르면 비교가 불가능하고, (b) 잘려나가는 건 **쉬운 에포크(낮에 깨어있음)** 뿐이라 어려운 문제를 회피하는 게 아니며, (c) 점수가 **내려가는** 방향이라 자기한테 유리한 조작이 아닙니다.

> **추천: ±60 에포크.** 다만 **자르기 전/후 수치를 둘 다 뽑아 두면** 이 선택의 영향을 정량적으로 말할 수 있습니다. 실험 항목 하나로 넣을 가치가 있습니다.

# D6. 필터링

원신호에서 관심 없는 주파수를 걸러낼지 정합니다.

| 선택지 | 설정 | 쓰는 곳 |
|---|---|---|
| **안 함** | — | **DeepSleepNet** (원신호 그대로 CNN에 넣음) |
| **FIR 밴드패스, 영위상** | 0.4–30 Hz (`mne.filter.filter_data`) | **YASA** |
| **IIR 밴드패스, 인과** | Butterworth 5차, 0.4–30 Hz (`lfilter`) | **sleep-linear** |

### 알아야 할 개념 두 개

**영위상 vs 인과**
- **인과(causal)** 필터는 과거만 보고 계산합니다. 실시간 가능. 대신 **파형이 시간축에서 밀립니다**(위상 왜곡).
- **영위상(zero-phase)** 필터는 앞뒤로 두 번 통과시켜 밀림을 상쇄합니다. 실시간 불가. `filtfilt` / `sosfiltfilt`.

**FIR vs IIR**
- **FIR**: 계수가 많아 느리지만 안정적이고 위상 특성이 깔끔합니다.
- **IIR**(Butterworth 등): 계수가 적어 빠르지만 위상이 비선형입니다.

### 트레이드오프

제가 앞서 "인과 필터는 위상 왜곡이 있어 틀렸다"고 말씀드렸는데 **과했습니다.**
DeepSleepNet을 이긴 sleep-linear이 바로 그 인과 IIR을 씁니다. **30초 구간의 통계량(분산, 대역파워)은 위상에 둔감**하기 때문일 가능성이 큽니다.

그리고 **EDFX는 이미 하드웨어에서 필터링돼 있습니다** (HP 0.5Hz / LP 100Hz). 추가 필터가 꼭 필요한지 자체가 열린 질문입니다.

> **추천: 영위상 밴드패스 0.4–30 Hz를 기본으로.** 다만 이건 **A/B 실험 1순위 후보**입니다 — 필터 없음 / 영위상 / 인과 셋을 비교하면 "비교했더니 이랬다"가 바로 나옵니다.

# D7. 아티팩트 처리

몸을 뒤척이거나 전극이 떨어지면 신호가 튑니다. 어떻게 할지 정합니다.

| 선택지 | 방식 | 쓰는 곳 |
|---|---|---|
| **아무것도 안 함** | 대신 **중앙값 Welch**로 견딤 | **YASA** |
| **진폭 임계값으로 표시** | ptp > 500µV인 에포크를 마스킹 | 우리 기존 전처리 |
| **클리핑** | 전역 IQR × 20을 넘으면 잘라냄 | **U-Time** (`clip_noisy_values`) |
| **에포크 제거** | 아예 버림 | — |

**우리 실측**: 500µV 기준은 **EDFX에서 검출률 0.00%** 입니다. EDFX 신호가 최대 353µV까지밖에 안 가서 임계값이 아예 안 걸립니다. **마스크가 없는 것과 같습니다.**

**YASA의 접근이 흥미롭습니다.** 아티팩트를 제거하는 대신 **Welch 스펙트럼을 계산할 때 평균이 아니라 중앙값**을 씁니다. 30초 중 1초에 잡음이 껴도 중앙값은 안 흔들립니다. 문제를 제거가 아니라 **강건한 통계량**으로 푸는 겁니다.

**주의**: 에포크를 제거하면 **평가 대상이 달라져서** 남과 비교가 안 됩니다. 어려운 에포크만 골라 버리면 점수가 부당하게 오릅니다.

> **추천: 제거하지 않음.** 대신 중앙값 Welch를 특징 추출 단계에서 쓰고, **아티팩트 지표는 계산해서 저장만** 해 둡니다(나중에 "아티팩트 많은 에포크에서 성능이 떨어지나"를 분석할 수 있게).

# D8. 중간 산출물을 어떤 형식으로 저장하나

| 선택지 | 크기 | 특징 |
|---|---|---|
| **npz (녹음당 1개)** | 신호를 담으면 원본과 비슷 (~46GB) | numpy만 있으면 됨. 병렬화·부분 재빌드 쉬움 |
| **parquet (녹음당 1개)** | 특징만 담으면 1–3GB | 컬럼 단위 읽기, pandas 친화 |
| **HDF5 하나로** | — | 필요한 구간만 슬라이스 가능. **동시 쓰기 문제 있음** |

**중요한 제약**: 서버 디스크 여유가 **103GB**뿐입니다 (3.2TB 중 97% 사용, 3주 전엔 356GB였음).

**신호를 담은 중간 파일은 원본만큼 큽니다.** 특징만 담으면 1–3GB입니다.

> **추천: 2단계 구조.**
> - 1단계: EDF → **에포크 신호 npz** (녹음당 1개). 필터·절단·라벨 적용 완료 상태
> - 2단계: npz → **특징 parquet**
>
> 1단계를 남기는 이유는 **특징 설계를 계속 바꿀 것이기 때문**입니다. 특징을 바꿀 때마다 EDF를 다시 파싱하면 느립니다.
> 특징이 확정되면 1단계를 지워서 디스크를 회수합니다.

# D9. 재실행 정책

| 선택지 | 특징 |
|---|---|
| **매번 전체 재빌드** | 단순. 출력 디렉터리를 지우고 시작 |
| **멱등 재개** | 출력이 있고 설정 해시가 같으면 건너뜀. `--overwrite`로 강제 |

**DeepSleepNet과 TinySleepNet 둘 다 시작할 때 `shutil.rmtree`로 출력 디렉터리를 지웁니다.** 중간에 끊기면 처음부터입니다.

> **추천: 멱등 재개.** 15줄이면 됩니다. 153개 파일을 돌리다 중간에 끊겼을 때 처음부터 다시 안 해도 되고, **"설정이 바뀌면 다시 계산"이 자동으로 됩니다.**
