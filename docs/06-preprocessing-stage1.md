# 1단계 전처리 — 결정과 근거

EDF 원본을 에포크 npz 로 바꾸는 단계. **선택지·근거·최종 결정·실행 결과**를 한 문서에 둔다.

전제: EDFX Sleep-Cassette 단독 / Fpz-Cz + Pz-Oz / 4-class / 100 Hz / 피험자 단위 CV.
2단계(특징 추출) 설계는 [`07-preprocessing-stage2.md`](07-preprocessing-stage2.md).

---

## 0. 설계 원칙 — 이게 나머지를 다 결정한다

> **되돌릴 수 없는 처리를 중간 산출물에 굽지 않는다.**

```
[1단계] EDF ──→ 에포크 npz     정보를 잃지 않는 처리만  (9.3 GB, 만드는 데 시간이 든다)
                    ↓
[2단계] npz ──→ 특징 parquet   비교 대상이 되는 처리 전부 (설정만 바꿔 몇 번이고 다시)
```

필터를 1단계에 구우면 "필터 없음 vs 영위상 vs 인과" 를 비교할 때마다 **EDF 153개를 다시 파싱**해야 한다.
2단계에 두면 npz 를 그대로 두고 설정만 바꾼다.

**비교 실험이 이 프로젝트의 결과물**이므로, 비교 대상이 되는 처리는 전부 뒤쪽에 있어야 한다.

**레퍼런스 비교**
DeepSleepNet·TinySleepNet 은 1단계만 있고 필터를 아예 안 건다(원신호를 그대로 CNN 에).
sleep-linear 은 노트북 하나에서 전부 처리해 중간 산출물이 특징 parquet 뿐이라, 필터를 바꾸려면 전부 다시 돌린다.
U-Time 은 `ut preprocess` 로 스케일링·QC·리샘플링을 H5 에 굽는 옵션이 있는데, **그래서 그걸 바꾸려면 재생성이 필요하다.**

## D1. EDF 리더 — MNE

| | MNE | pyedflib |
|---|---|---|
| 주석(hypnogram) 읽기 | **내장** (`read_annotations`) | 직접 파싱 |
| 에포크화 | `Epochs` 객체 | **레코드 reshape 로 공짜** |
| 속도·메모리 | 느리고 무겁다 | **가볍고 빠르다** |
| 단위 | 자동 (볼트로 통일) | 수동 |
| YASA 연결 | **입력이 MNE Raw** | 변환 계층 필요 |

**고른 이유.** hypnogram 파싱이 한 줄이다. DeepSleepNet 은 그것 때문에 `dhedfreader.py` 를
직접 만들어 번들했고, 그게 그 코드가 지저분한 이유 중 하나다.
나중에 YASA 를 비교군으로 돌릴 때도 MNE Raw 를 그대로 넘길 수 있다.

**트레이드오프.** MNE 는 "뇌파로 할 수 있는 모든 것" 을 위한 도구라 EDF 읽기 하나에는 과잉이다.
pyedflib 는 EDF 레코드 구조(EDFX 는 30초 레코드)를 그대로 reshape 해 에포크를 공짜로 얻는다.
**다만 153개 규모에서 속도는 병목이 아니다.** 수만 개였다면 pyedflib 를 골랐을 것이다.

> 레퍼런스: MNE — YASA, DeepSleepNet, U-Time / pyedflib — TinySleepNet, sleep-linear

## D2. 파일 짝짓기 — 정규식 + 시작시각 검증

```
SC4001E0-PSG.edf         ┐  앞 7자 "SC4001E" 공통, 8번째만 다름
SC4001EC-Hypnogram.edf   ┘  앞 5자 = 피험자, 6번째 = 몇째 밤
```

**왜.** DeepSleepNet 은 두 목록을 정렬해 **인덱스 i 끼리** 짝짓는다.
파일이 하나 빠지면 이후 전부 어긋나는데 **아무 소리도 나지 않는다.**

거기에 더해 **PSG 측정 시작시각 == hypnogram 기준시각** 을 확인한다.
어긋나면 라벨이 통째로 밀린 채 학습이 조용히 성공한다 — 가장 찾기 어려운 종류의 버그다.

**실행 결과: 153개 전부 통과.** 어긋난 파일은 없었다.

> 레퍼런스: TinySleepNet(`get_subject_files`), U-Time(`psg_regex`/`hyp_regex` YAML)

## D3. 라벨 매핑 — 4-class, 사유는 나눠서 센다

```yaml
"Sleep stage W": 0                          # W
"Sleep stage 1": 1,  "Sleep stage 2": 1     # LS  (N1 + N2)
"Sleep stage 3": 2,  "Sleep stage 4": 2     # DS  (R&K 4단계 → AASM N3)
"Sleep stage R": 3                          # R
drop: ["Sleep stage ?", "Movement time"]
```

**왜 사유를 나누나.** DeepSleepNet 은 둘 다 `UNKNOWN=5` 로 묶는다. TinySleepNet 은 나눈다.
나눠두면 "판독 불가가 많은 녹음이 성능이 나쁜가" 를 나중에 볼 수 있다. 묶으면 못 한다.

**모르는 주석은 예외를 던진다.** 조용히 배경으로 흘려보내면 나중에 못 찾는다.

## D4. 판독불가 에포크 — 제거하되 원본 번호를 남긴다

**실측 (153개 전수).**

| | 에포크 |
|---|---:|
| `Sleep stage ?` 전체 | 25,047 |
| ┗ 신호가 끝난 뒤 구간 | 23,712 |
| ┗ **신호 안에 있는 것** | **1,335** |
| `Movement time` | 128 |

`Sleep stage ?` 의 대부분은 **녹음이 끝난 뒤에도 주석만 이어진 구간**이다.
판독할 신호가 아예 없어 채점자가 `?` 로 남긴 것이고, 애초에 처리 대상이 아니다.
신호 안에 실제로 있는 건 **1,463개 = 전체의 0.35 %**.

> 앞서 "297건" 이라고 적었던 건 **주석 건수**였다. 주석 하나가 여러 에포크를 덮는다.

**제거하는 이유.** 정답이 없어 학습에도 평가에도 못 쓴다. 되살릴 시나리오가 없다.
U-Time 은 제거 대신 손실에서 마스킹하는데, **부스팅 트리는 행 단위라 마스킹 개념이 없다.**

**부작용과 대응.** 중간 에포크를 지우면 시간축에 구멍이 생긴다.

```
원본     ... 409  410  411  [?]  [?]  414  415 ...
저장 후  ... 409  410  411       414  415 ...
                          └ 411 다음이 414. 30초가 아니라 90초 간격
```

2단계에서 "직전 몇 분의 평균" 같은 이웃 참조 특징을 쓸 때 구멍을 모르면
"1분 전" 이 실제로는 3분 전일 수 있다.

→ **원본 에포크 번호(`epoch_idx`)를 함께 저장한다.** 195,479 × 4바이트 = 0.8 MB 로 끝난다.

**실행 결과: 시간축 구멍 총 1,104개.**

## D5. Wake 절단 — 경계만 기록하고 자르지 않는다

```python
w_edge = 60                                   # 30분 = 60 에포크
nw = np.flatnonzero(labels != W)
lo, hi = max(0, nw[0] - w_edge), min(len(labels), nw[-1] + w_edge + 1)
```

DeepSleepNet `prepare_physionet.py` 의 `w_edge_mins = 30` × 2 와 같다.

**왜 자르나.** 안 자르면 W 가 68.8 % 라 **다수클래스만 찍어도 68.8 %** 가 나온다.
잘려나가는 건 대부분 "낮에 멀쩡히 깨어 있는" 구간이라 임상적으로 무의미하다.

**약점을 알고 간다.** 자를 위치를 정하려고 **정답 라벨을 본다.**
배포 시점엔 라벨이 없으니 엄밀히는 재현 불가능한 처리다.
방어: (a) 벤치마크 관행, (b) 잘리는 건 쉬운 에포크뿐, (c) 점수가 **내려가는** 방향(46.4 % 기준선).

**그래서 자르지 않고 경계만 저장한다.** `crop_lo` / `crop_hi` 두 정수뿐이다.
"절단 vs 미절단" 을 npz 재생성 없이 2단계에서 비교할 수 있다.

> 대안: `SC-subjects.xls` 의 `LightsOff` 를 쓰면 **시작점은 라벨 없이** 정할 수 있다.
> 다만 `LightsOn` 이 없어 끝점은 여전히 라벨이 필요하다. 부가 실험으로 남긴다.

## D6. 필터 — 1단계에서는 걸지 않는다

1. **EDFX 는 하드웨어에서 이미 필터링됐다** (HP 0.5 Hz / LP 100 Hz). 추가 필터가 필요한지 자체가 열린 질문이다.
2. **대역파워를 Welch PSD 로 내면 시간영역 밴드패스가 불필요하다.** YASA·sleep-linear 둘 다 PSD 로 낸다.
3. **§0 원칙** — 필터는 정보를 잃는 처리라 A/B 대상이다.

**2단계에서 셋을 비교한다**: 없음 / `sosfiltfilt` 영위상 0.4–30 Hz / `lfilter` 인과 0.4–30 Hz.

> 레퍼런스: DeepSleepNet **없음** / YASA **FIR 영위상** 0.4–30 Hz / sleep-linear **Butterworth 인과** 0.4–30 Hz
> — 세 레포가 세 가지를 다 쓴다. **정답이 정해져 있지 않다는 뜻**이므로 우리가 재는 게 맞다.

## D7. 아티팩트 — 제거하지 않고 지표만 저장

| 지표 | 용도 |
|---|---|
| `ptp` (peak-to-peak) | 진폭 이상 |
| `std` | 진폭 이상 |
| `flat_ratio` (연속 동일값 비율) | 전극 탈락 |

**왜 제거하지 않나.**

- **제거하면 평가 대상이 실험마다 달라져 비교가 깨진다.** 어려운 에포크만 골라 버리면 점수가 부당하게 오른다.
- **YASA 는 수면 단계 분류 경로에서 아티팩트 제거를 아예 안 한다.** 대신 Welch 를 평균이 아니라
  **중앙값**으로 집계해 견딘다 — 제거가 아니라 **강건한 통계량**으로 푸는 접근이다.
- 구 파이프라인의 500 µV 임계값은 **EDFX 에서 검출률 0.00 %** 였다. EDFX 최대 ptp 가 약 353 µV 라
  절대 안 걸린다. HMC 는 13.99 % 가 걸리는데 대부분 ±800 µV 하드 클리핑이다.
  **임계값 하나로 두 데이터셋을 다룰 수 없다는 실패 사례다.**

**실행 결과: `flat_ratio` 최대 0.200.** 전극 탈락(1.0) 은 없었다.

> 레퍼런스: YASA(제거 안 함, 중앙값 Welch) / U-Time(`clip_noisy_values`, 전역 IQR×20 클리핑)

## D8. 저장 — 녹음당 npz 하나

```python
SC400N1.npz
  data        (n_ep, 2, 3000) float32   신호. µV
  labels      (n_ep,)         int8      0=W 1=LS 2=DS 3=R
  epoch_idx   (n_ep,)         int32     원본 에포크 번호 (구멍 추적)
  crop_lo, crop_hi                      자르지 않고 경계만
  ptp, std, flat_ratio  (n_ep, 2) float32
  subject, night, sfreq, ch_names, unit, config_hash
```

**왜 녹음당 파일인가.** 피험자 단위 교차검증과 맞아떨어진다.

```
녹음당 파일    fold 1 학습셋 = [SC400N1.npz, SC400N2.npz, ...]   ← 그냥 파일 목록
단일 HDF5      fold 1 학습셋 = 행 12,043~28,551 + 31,002~44,120  ← 인덱스 계산
```

파일명이 곧 피험자 키라서 **분할이 파일 목록 그 자체**가 된다.
인덱스 계산이 끼면 거기서 틀릴 여지가 생기고, **데이터 누수는 늘 그런 곳에 숨는다.**
덧붙여 병렬화가 자명하고(프로세스마다 다른 파일), 하나가 깨져도 그것만 다시 만든다.

**왜 HDF5 하나가 아닌가.** U-Time 이 그렇게 하는데, 자기 코드에
**"HDF5 가 스레드 안전하게 컴파일돼야 한다"** 는 경고를 달아뒀다. 우리 규모에선 얻는 게 없다.

**왜 float32 인가.** EDF 는 규격상 int16 으로 저장하므로 int16 + 배율이면 용량이 절반(4.7 GB)이 된다.
하지만 읽을 때 배율 곱하기를 한 곳에서라도 빠뜨리면 **엉뚱한 스케일로 학습되는데 에러가 안 난다.**
서버 여유가 충분해 **조용히 틀릴 위험을 피하는 쪽**을 골랐다.

> 레퍼런스: 녹음당 파일 — DeepSleepNet, TinySleepNet, U-Time, SLEEPYLAND **전부**

## D9. 멱등 재개 — 설정 해시로 건너뛴다

설정 YAML 을 sha256 으로 줄여 npz 안에 저장하고, 재실행 때 비교해서 같으면 건너뛴다.

**왜.** DeepSleepNet·TinySleepNet 은 시작할 때 출력 디렉터리를 `shutil.rmtree` 한다.
153개를 돌리다 100번째에서 끊기면 **처음부터**다.

**실행 결과: 재실행이 몇 초에 끝난다.** 건너뛴 녹음의 통계는 이전 매니페스트에서 되살려
집계가 0 이 되지 않게 했다.
